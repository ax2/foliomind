## 0. 文档说明

### 0.1 背景

我们的背景描述了一款面向职场人士（上班族）的 A 股盯盘智能体：7×24 小时监控行情、公告、资金与产业事件，在异动发生时**1 分钟内**给出「发生了什么 → 为什么 → 与你持仓的关系 → 接下来关注什么」的解读，并辅以止盈止损纪律提醒与产业事件日历预警。

FolioMind 是已具备自选股、组合持仓、盯盘规则、告警去重、站内消息与 QVeris 数据适配器的金融研究 Agent。本文档的目标：**在 FolioMind 现有能力之上，规划出完整实现该产品所需的功能清单、优先级、数据需求与里程碑。**

### 0.2 产品原则（贯穿所有功能）

| 原则 | 说明 | 违反示例（禁止） |
|-|-|-|
| 不荐股、不预测点位、不承诺收益 | AI 只做证据摘要、成因分析与风险提示 | 「建议买入/加仓」「目标价必到」「稳赚」 |
| 所有 AI 输出带免责声明 | 标注信息来源、数据截至时间 | 无来源的确定性结论 |
| 数据真实、缺失即空 | 无真实数据不臆造，数据时间未知/延迟需明确标注 | 用样例数据冒充实时行情 |
| 全链路可审计 | 对话、盯盘触发、提醒记录留痕 ≥6 个月 | 无法回溯某条提醒为何触发 |
| 隐私最小化 | 仅采集业务必需数据，敏感数据加密 | 采集与功能无关的个人信息 |

### 0.3 术语

| 术语 | 含义 |
|-|-|
| 盯盘规则（Rule） | 用户创建的一组监控条件（价格/量能/事件…），持续评估，触发边沿才告警 |
| 异动（Anomaly） | 行情/量能/资金在短时间窗口内偏离常态的事件 |
| AI 归因（Attribution） | 基于 RAG 聚合新闻、公告、板块信息解释异动成因 |
| 交易计划（Plan） | 一笔交易的完整档案：买入逻辑、目标价、止损价、催化事件、复盘记录 |
| 事件日历（Event Calendar） | 财报/解禁/宏观/产业/政策事件的时序聚合与预警 |

## 1. 产品概述

### 1.1 定位

> **替上班族看盘的 AI 盯盘员** —— 不只做价格提醒，而是懂产业、懂逻辑、懂用户持仓的智能盯盘 Agent。

核心价值主张：

1. **省时间**：不盯盘也能捕捉关键价格信号与趋势拐点，只在重要时刻通知。
2. **不错过**：政策利好、业绩预告、龙虎榜异动等持仓关键事件毫秒级监控、第一时间推送。
3. **懂逻辑**：拆解涨跌背后的产业趋势、资金动向与事件影响。
4. **守纪律**：止盈止损到价提醒 + 交易计划跟踪，克制情绪化操作。

### 1.2 目标用户

| 用户类型 | 画像 | 核心诉求 |
|-|-|-|
| 稳健型上班族 | 25–45 岁、月薪 1–4 万、持仓 3–5 只、1–5 年经验 | 持仓风险预警、关键公告同步、不踩雷 |
| 硬科技掘金者 | 深耕 AI/半导体等赛道 | 产业政策与技术突破的深度解读、事件驱动提醒 |
| 纪律型交易者 | 严格执行交易计划 | 精准价格触发、止盈止损强通知 |

### 1.3 典型使用场景（一天时间轴）

| 时段 | 场景 | 对应功能 |
|-|-|-|
| 08:00 | 盘前早知道：通勤看隔夜公告/行业重磅/外盘 | F3 盘前简报 |
| 盘中 | 持仓异动 AI 自动解读（政策/资金/事件） | F2 异动解读 |
| 14:00 | 尾盘止盈止损、价格预警强提醒 | F4 纪律提醒 |
| 15:30 | 盘后自动复盘 + 明日关注 | F3 盘后复盘 |
| 20:00 | 财报/公告 AI 摘要、次日市场前瞻 | F3 夜间覆盖 + F5 事件日历 |

## 4. 功能详述

### F1 智能盯盘条件中心

**目标**：让用户以「条件 → 组合 → 启用」三步建立个性化盯盘，AI 辅助降低配置门槛。

#### 4.1 六类条件类型

| 条件类别 | 子能力 | 数据源需求 | 备注 |
|-|-|-|-|
| 价格触发 | 涨跌幅阈值、突破/跌破关键价位 | 实时行情 L1 | MVP 核心，≤3s |
| 量能异动 | 成交量突放、换手率异常 | 实时行情（量/换手） | 需要量比计算 |
| 技术形态 | 均线金叉死叉、创新高/新低、平台突破 | 日线/分钟线历史序列 | P1，需本地技术指标计算 |
| 核心事件 | 财报发布、重大公告、股东增减持、龙虎榜 | 公告/龙虎榜/股东数据 | 事件驱动，非轮询 |
| 主力资金 | 北向资金、主力净流入、两融余额 | 北向/资金流/两融数据 | 注意：QVeris 主力资金 7.2cr/次无批量 |
| 产业舆情 | 行业政策、产业链动态、突发舆情 | 新闻舆情 | RAG 检索 |

#### 4.2 需求条目

| # | 需求 | 验收要点 | 优先级 |
|-|-|-|-|
| F1-01 | 支持 6 类条件创建，每类含参数配置表单 | 6 类均可创建、参数可保存 | P0 |
| F1-02 | 条件支持 AND/OR 逻辑组合（同一股票多条件叠加） | 组合生效、单条条件可独立启停 | P0 |
| F1-03 | 预置 4 套场景模板（如「上班族」「中线持仓」） | 一键启用即生成一组条件 | P1 |
| F1-04 | AI 基于持仓自动推荐盯盘条件 | 推荐项可一键采纳 | P2 |
| F1-05 | 免费用户限 5 条、专业无上限（服务端强制） | 超限创建被拦截并引导升级 | P1 |
| F1-06 | 条件列表页：状态、触发时间线、最近触发详情 | 与现有盯盘规则页融合 | P0 |
| F1-07 | 条件触发与告警边沿去重复用现有机制 | 条件持续成立不重复刷屏 | P0 |

### F2 实时异动监控与 AI 解读

**目标**：异动触发后 1 分钟内给出「发生了什么 → 为什么 → 与持仓的关系 → 后续关注」。

#### 4.3 异动检测引擎

| 检测类型 | 判定规则（建议初值，可配置） | 优先级 |
|-|-|-|
| 价格急涨急跌 | 5 分钟内涨跌幅 ≥ 阈值（如 ±4%） | P0 |
| 量能异常 | 量比 ≥ 2.5 或 5 分钟量能较近期均值放大 N 倍 | P0 |
| 资金异动 | 主力净流入/流出绝对值突破阈值 | P1 |
| 板块联动 | 同板块 ≥3 只同步异动 | P2 |

#### 4.4 AI 归因与解读（F2 核心）

解读卡片需包含四段结构化内容（对齐 PPT 示例）：

1. **异动事实**：标的、方向、幅度、当前价、量比、触发时间。
2. **异动背后的诱因**：板块联动、市场传闻、公司公告、资金面等，每点附信息源。
3. **与您持仓的关联**：持仓数量、成本、浮动盈亏、距止损线空间、账户影响评估。
4. **后续关注重点**：关键支撑/压力位、催化剂事件（如财报/宏观数据）、需验证的传闻。

| # | 需求 | 验收要点 | 优先级 |
|-|-|-|-|
| F2-01 | 异动检测基于实时行情轮询数据计算，不额外消耗模型调用 | 检测纯计算，模型仅用于解读 | P0 |
| F2-02 | 解读生成走 RAG：聚合新闻、公告、板块数据后调用 LLM | 输出含来源链接与数据截至时间 | P0 |
| F2-03 | 解读与持仓强关联：引用用户持仓成本/盈亏（仅用户本人可见） | 持仓数据不出隔离边界 | P0 |
| F2-04 | 免费用户每日 3 次解读额度，专业无限（服务端限流） | 超限提示升级 | P1 |
| F2-05 | 每条解读附免责声明（不构成投资建议） | 必现、不可省略 | P0 |
| F2-06 | 解读卡片可展开查看完整来源列表 | 可追溯 | P1 |
| F2-07 | 异动→解读端到端延迟 ≤30s（MVP）/ ≤10s（成长期） | 含检测+归因+推送 | P0 |

### F3 持仓全周期监控

**目标**：盘前 → 盘中 → 盘后 → 夜间/周末，7×24 覆盖持仓相关关键节点。

#### 4.5 四时段能力

| 时段 | 内容 | 交付形态 | 优先级 |
|-|-|-|-|
| 08:00 盘前 | 持仓股公告摘要、行业动态、宏观事件、隔夜外盘 | 定时简报（AI 生成摘要） | P0 |
| 盘中 | 价格异动 AI 解读、止盈止损提醒、板块联动、资金流 | 实时推送（复用 F2/F4） | P0 |
| 15:30 盘后 | 当日表现全览、账户盈亏统计、晚间公告提示、明日关注 | 自动复盘报告 | P0 |
| 夜间/周末 | 晚间公告/财报、突发利好利空、外盘与大宗联动、政策新规 | 事件驱动推送 | P1 |

| # | 需求 | 验收要点 | 优先级 |
|-|-|-|-|
| F3-01 | 定时任务调度：按交易日历在 08:00/15:30 触发简报生成 | 非交易日不触发；失败重试 | P0 |
| F3-02 | 盘前简报内容 = 持仓公告摘要 + 行业/宏观 + 外盘 | 信息带来源与时间戳 | P0 |
| F3-03 | 盘后复盘 = 当日表现 + 盈亏 + 明日关注点 | 复盘存为可回顾记录 | P0 |
| F3-04 | 夜间监控：公告/新闻增量扫描（30min 兜底 + 事件驱动） | 与 F5 日历数据源复用 | P1 |
| F3-05 | 免费版简报为通用简版，专业版按持仓偏好定制 | 权益差异化在服务端生效 | P1 |

### F4 纪律提醒与交易计划跟踪

**目标**：把「买了就忘、赚小亏大」的人性弱点交给机器。

#### 4.6 止盈止损强提醒

| # | 需求 | 验收要点 | 优先级 |
|-|-|-|-|
| F4-01 | 用户可为持仓设置止盈/止损价，自动加入实时盯盘队列 | 到价即触发，与行情轮询同频 | P0 |
| F4-02 | 触发时多渠道强提醒：站内 + 系统通知（+ 专业短信） | 消息必达；记录触发明细 | P1 |
| F4-03 | 提醒卡片含：原计划、当前价、建议（严守纪律，非调仓指令） | 文案合规（不构成投资建议） | P0 |

#### 4.7 交易计划全流程跟踪

| # | 需求 | 验收要点 | 优先级 |
|-|-|-|-|
| F4-04 | 创建交易计划档案：买入逻辑、目标价、止损价、计划周期 | 一笔交易一个档案 | P1 |
| F4-05 | 价格目标监控：实时追踪现价与目标/止损偏离度、盈亏比 | 数值动态更新 | P1 |
| F4-06 | 催化事件追踪：关联财报/政策/行业利好事件（对接 F5 日历） | 事件临近/发生自动提醒 | P1 |
| F4-07 | 逻辑证伪预警：基本面/技术面质变时提示风险 | 基于数据规则，非主观判断 | P2 |
| F4-08 | 定期复盘提醒：按周/月生成计划执行报告 | 报告可导出 | P2 |
| F4-09 | 用户可操作「我已执行 / 调整价格」，状态回写档案 | 操作留痕 | P1 |

### F5 产业事件日历预警

**目标**：财报、解禁、宏观、产业、资金、政策事件提前预警，打有准备之仗。

#### 4.8 事件类型与预警策略

| 事件类型 | 数据示例 | 提前触达 | 优先级 |
|-|-|-|-|
| 上市公司财报 | 中报/年报披露日 | 提前 7 天 + 当天强提醒 | P0 |
| 限售股解禁 | 解禁数量、涉及机构 | 提前 7 天 + 当天强提醒 | P1 |
| 宏观经济数据 | CPI/PPI/非农 | 提前 1 天 | P1 |
| 产业事件 | 行业峰会、技术发布 | 提前 1–3 天（按重要性分级） | P1 |
| 资金动向 | 北向、两融、解禁资金压力 | 事件驱动 | P2 |
| 政策窗口 | 政策发布/落地时间 | 提前 1–3 天 | P1 |

| # | 需求 | 验收要点 | 优先级 |
|-|-|-|-|
| F5-01 | 事件日历聚合展示：月视图 + 列表视图 | 与现有 UI 风格一致 | P0 |
| F5-02 | 「只看持仓相关」一键筛选 + 自定义关注行业 | 筛选服务端生效 | P0 |
| F5-03 | 双重预警：提前 7 天 + 事件当天再提醒 | 不重复刷屏（去重） | P0 |
| F5-04 | 事件详情：时间、影响标的、相关度说明 | 带来源 | P1 |
| F5-05 | 财报/宏观/政策数据接入（QVeris 可用） | 见 §5 数据映射 | P0 |
| F5-06 | **解禁日历数据源缺失问题（P0 风险）**：QVeris 无解禁专用工具，需外采或接入交易所/第三方授权源，**数据未验证前不得作为售卖点** | 见 §9 风险 | P1 |

### F6 会员分层与商业闭环

**目标**：免费验证价值 → 高频建立依赖 → 付费解锁全量（参考转化率 3%–5%）。

| 权益点 | 免费版 | 专业版（199 元/年） | 优先级 |
|-|-|-|-|
| 盯盘条件数量 | 5 条 | 无上限 | P1 |
| 自选股上限 | 10 只 | 无限制 | P1 |
| 价格/涨跌预警 | 基础提醒 | 毫秒级多维度触发 | P1 |
| 公告资讯解读 | 原文展示 | AI 摘要直达 | P1 |
| AI 异动解读 | 3 次/日 | 无限次深度归因 | P1 |
| 盘前/盘后简报 | 通用简版 | 持仓定制化 | P1 |
| 资金面/主力监控 | 不支持 | 实时监控 | P1 |

## 6. 技术架构演进

> 现状架构（Tauri + Rust Host + Pi runtime + QVeris 适配器）已满足桌面/本地 Web 形态。增量建设聚焦「盯盘引擎增强」与「AI 解读编排」。

```text
[ 接入层 ] 桌面端(现有) · 本地 Web(现有) · 小程序/PWA(Phase3, 待建)
                 │
[ 应用层 ] 用户/持仓/自选(现有) ── 新增：盯盘规则引擎升级 · 简报生成 · 交易计划 · 事件日历 · 会员权益
                 │
[ Agent 编排 ] Pi runtime(现有) ── 新增：异动解读 Skill · 盘前盘后简报 Skill · 事件摘要 Skill
                 │
[ 智能引擎 ] RAG(现有) ── 新增：异动归因模板 · 技术指标计算(本地) · 事件重要性分级
                 │
[ 数据层 ] QVeris 适配器(现有) ── 新增：公告/新闻/日历工具映射 · 解禁数据源(外采) · 增量游标
```

### 6.1 关键设计决策

| 决策点 | 方案 | 理由 |
|-|-|-|
| 异动检测放在哪 | **前端/客户端计算**（基于行情轮询数据阈值判断），模型只做解读 | 省 token、毫秒级、与现有「WebView 调度盯盘」一致 |
| 解读生成放哪 | Pi runtime + 专用 Skill（`anomaly-attribution`、`daily-briefing`、`market-review`） | 复用现有 RPC/审计/取消机制 |
| 调度升级 | 现有 30s 盯盘检查 → 分层调度：行情轮询（15s/180s 分级）+ 定时简报（08:00/15:30 交易日）+ 事件扫描（30min） | 满足 F1/F2/F3 全时段覆盖 |
| 简报与复盘 | 定时任务触发 Pi Skill 生成，结果落站内消息 | 与现有消息中心统一 |
| 交易计划 | 新增数据模型（Plan），存 user-state 或独立文件，Host 管理 | 延续现有持久化边界 |
| 会员权益 | Host 侧权益配置 + 服务端校验（免付费功能本地也校验） | 防止绕过 |
| 微信/短信（P2） | 预留推送网关接口，Phase2 后接入 | 依赖资质，不阻塞主流程 |

### 6.2 性能与 SLA（对齐 PPT 承诺 + 可行性修正）

| 指标 | PPT 承诺 | 落地目标（MVP→成长期） | 可行性说明 |

## 11. 产品设计更新与渐进式重构

### 11.1 这次更新解决什么问题

v1.0 已经完成了功能蓝图，但对用户每天打开产品时最重要的三个问题描述还不够具体：

1. **我现在看到的数据是否真实、来自哪里、截至什么时候？**
2. **没有数据时，我应该等待、重试，还是检查配置？**
3. **从行情到盯盘、组合、研究和对话，下一步动作是否清晰？**

v1.1 将产品设计收敛为「真实数据工作台 + 可解释的 Agent」：行情、盯盘、组合和研究是主工作区，Agent 负责解释和行动编排；数据来源、时间、新鲜度和失败原因在主界面可见，但不以供应商品牌作为产品主叙事。

### 11.2 设计原则（新增）

| 原则 | 设计要求 | 验收方式 |
|-|-|-|
| 数据先于结论 | 先展示值、来源、时间和新鲜度，再展示 AI 解读 | 任意行情卡都能找到 source/as-of |
| 渐进披露 | 默认只显示当前决策所需信息，详情和原始调用按需展开 | 首屏不超过一个主要任务 |
| 可恢复 | 每个可恢复失败都提供明确的重试或去设置动作 | 无死路错误状态 |
| 页面同构 | Web 本地调试和桌面端共享同一信息架构、状态和快捷动作 | 同一操作的文案与状态一致 |
| 渠道可替换 | UI 只认识稳定的 FolioMind 数据契约，不绑定供应商工具名 | provider 变化不改页面组件 |
| 克制的金融语义 | 红/绿只表达涨跌，不表达推荐；不使用虚构数字填充空位 | 视觉与文案审查 |

### 11.3 信息架构与导航

桌面端使用「左侧主导航 + 中央工作区 + 右侧 Agent」三栏结构；Web 本地调试保持同一结构，在窄屏时折叠为单栏。主导航顺序调整为：

`自选 / 行情` → `盯盘` → `组合` → `研究` → `事件` → `消息` → `对话` → `设置`

- 自选/行情是默认落点，首屏只回答「标的现在怎么样」和「我可以做什么」。
- 盯盘聚焦条件、状态、触发时间线，不与聊天混排。
- 组合聚焦持仓事实、成本、当前值、风险和可导出报告。
- 研究聚焦筛选和比较；事件聚焦时间线与提醒。
- 对话是 Agent 工作区，不再承担数据源发现的可见流程。
- 开发面板是本地能力：Web 仅 localhost 可见，桌面端可从底部拉起；普通用户路径不出现。

### 11.4 视觉方向

采用「金融终端的密度 + 研究笔记的可读性」：

- 背景使用暖白和浅灰分层，内容卡片保持白底，避免仪表盘式大面积渐变。
- 主文字使用深墨色，蓝色表示可操作链接和当前选中，红/绿仅用于涨跌与风险方向。
- 数据来源和时间使用低对比度辅助文字，并通过状态点区分 fresh / stale / unknown。
- QVeris 只作为数据渠道标识（例如 `QVeris CAP · qveris_finance`），不作为 Logo、主标题或默认品牌露出。
- 图表、表格和消息卡共享同一间距、圆角和边框 token；移动端优先保证数值与操作不被截断。

### 11.5 核心页面设计

| 页面 | 用户任务 | 首屏必须看到 | 主要动作 | 空/失败状态 |
|-|-|-|-|-|
| 自选/行情 | 判断标的当前状态 | 价格、涨跌、数据健康条、图表 | 切换标的、刷新、加入盯盘、交给 Agent | 配置缺失 / 查询中 / 暂无数据 / 可能延迟 |
| 盯盘 | 管理规则并确认触发 | 规则状态、最近触发、未读告警 | 新建、启停、核实并分析、重试 | 尚无规则、数据源不可用 |
| 组合 | 了解账户事实与风险 | 市值、成本、盈亏、风险摘要 | 添加持仓、调整、导出报告 | 无持仓、无实时行情 |
| 研究 | 在真实行情中筛选 | 条件、结果数、数据时间 | 搜索、筛选、刷新、打开标的 | 无凭据、无返回数据、无匹配 |
| 事件 | 预先知道重要节点 | 时间线、相关标的、重要度 | 按持仓筛选、订阅、查看来源 | 数据源未覆盖、暂无事件 |
| 对话 | 用自然语言完成研究任务 | 当前上下文、来源和截至时间 | 查询、追问、打开证据 | 未配置模型、调用失败、取消 |
| 设置 | 配置数据与模型渠道 | 凭据状态、模型、渠道、同步状态 | 保存、同步模型、测试连接 | 保存失败、需要重新同步 |
| 开发面板 | 本地定位问题 | 调用日志、主要变量、Runtime 状态 | 刷新、重试、改本地变量 | 不记录密钥和原始提示词 |

### 11.6 真实数据状态规范

所有获取数据的页面必须使用同一套状态语义，不能各自编写「暂无数据」文案：

| 状态 | 触发条件 | 展示 | 可用动作 |
|-|-|-|-|
| `loading` | 请求尚未完成 | 骨架/“正在从已配置渠道获取真实数据” | 等待、取消（若支持） |
| `no-credential` | 未配置 API Key 或模型 | 空状态，不显示价格 | 去设置 |
| `empty` | 请求成功但没有该标的数据 | “暂无可用数据” | 重新获取、查看支持范围 |
| `stale` | 有数据但超过新鲜度阈值 | 值保留，标记“可能已延迟” | 刷新 |
| `partial` | 部分字段或部分标的成功 | 成功字段照常显示，缺失显示 `—` | 重试缺失部分 |
| `error` | 网络、权限或服务错误 | 友好短文案，不暴露内部堆栈 | 重试、去设置、打开开发面板 |
| `fresh` | 有可解析的时间且未过期 | 来源 + 数据时间 | 刷新 |

禁止：使用示例价格填充真实模式、把 `loading` 显示成 `—` 而不说明原因、把供应商错误码直接展示给用户、在对话中声明成功但页面没有对应数据。

### 11.7 数据展示契约

页面只消费 FolioMind 稳定契约，不直接依赖 QVeris 工具返回结构。当前 CAP 固化工具的外部能力契约如下：

| `kind` | 能力 | 必需参数 | 核心返回 |
|-|-|-|-|
| `quote` | `MKT.L1.RT` | `symbol` | price、change、changePercent、timestamp、volume、OHLCV |
| `details` | `REF.COMPANY_PROFILE` + `FUNDAMENTALS.DERIVED_RATIOS` | `symbol` | company、description、valuation、asOf |
| `series` | `MKT.BARS.EOD` | symbol、startDate、endDate | time、open、high、low、close、volume |
| `core_event` | `EVENT.CALENDAR.CORP` | `symbol`，可选 event_type、日期范围 | events、eventCount、date、type、title |
| `capital_flow` | `FLOW.LARGE_ORDER` | `symbol`，可选日期范围 | capitalFlow、mainNetInflow、date、net_flow |
| `sentiment` | `NEWS.FIN.TAGGED` | `symbol`，可选日期范围 | news、sentiment、sentimentScore、publishedAt |

默认 provider 为 `qveris_finance`，本地缓存保存工具 id、参数 schema、返回 schema、能力说明和目录版本；未来切换渠道时只替换适配层。页面应优先走固化 CAP，只有 CAP 不可用才回退发现流程。

2. 当前标的使用独立的 `selectedQuoteLoading[symbol]` 状态；后台整组行情刷新时仍可发起当前标的刷新，按钮文案明确显示“后台更新中”，不能把批量加载误报为当前请求已完成。
3. 未配置数据服务时主动作保持可用并进入设置；请求期间仅禁用当前标的按钮，避免重复提交。成功后继续复用组合止盈/止损边沿判断和系统通知；失败显示统一友好错误并允许再次获取。
4. “交给 Agent”单独进入对话，继续携带标的、provider 和真实数据约束；两条路径不互相伪造结果，行情页只消费返回的真实 quote。

验收：当前标的快速刷新不会触发对话消息；批量刷新进行中按钮仍可操作；成功只更新对应标的且保留其它行情；失败后可重试；未配置时一次点击进入设置；桌面/Web 共用同一状态和文案，Playwright 桌面/窄屏无控制台错误和水平溢出。

### 11.21 Stage 3E 统一行情证据抽屉（本轮增量）

为解决“行情看到了，但不知道来自哪里、是否新鲜、哪些字段缺失”的信任问题，在行情工作区和组合数据入口统一提供“来源与证据”抽屉。它只展示当前客户端已收到的真实响应，不新增模型编造或二次推断。

1. 抽屉展示数据渠道、Provider、返回来源、能力 ID（`MKT.L1.RT`）、数据截至时间、最近一次请求时间和新鲜度状态；没有时间戳时明确标记“数据时间未知”，超过新鲜度窗口时标记“行情可能已延迟”。
2. 对最新价、涨跌幅、昨收、开高低、成交量、成交额、市盈率和市净率逐字段展示覆盖情况；上游没有返回的字段保持空值（`—`），显示缺失字段列表，不从其它字段推算。
3. 抽屉提供当前标的独立重试。真实数据模式直接复用已固化 CAP 工具；未配置时按钮进入设置页。重试不会发起对话，也不会等待整组自选刷新。
4. 支持 Escape、关闭按钮和遮罩点击关闭，使用 modal 语义和打开时焦点落点；桌面端与本地 Web 共用组件，窄屏抽屉不产生水平溢出。
5. 抽屉不显示 API Key、原始响应或提示词，只保留用户理解数据可信度所需的脱敏元数据；所有空态、失败和部分字段响应均可恢复重试。

验收：真实行情打开抽屉可看到来源/渠道/能力/时间和字段覆盖；缺失字段不被填充；重试只更新当前标的；未配置时可直接去设置；Escape/遮罩可关闭；桌面/Web 在 1440px 和 390px 视口无控制台错误、无水平溢出。

### 11.22 Stage 3F 跨任务刷新恢复（本轮增量）

修复多页面同时消费行情能力时的竞争窗口：进入事件日历的瞬间若自选行情正在批量刷新，事件请求不能被静默跳过后永久停留在空白。

1. 事件页在行情批量刷新期间保持明确加载状态，不重复发起冲突请求；批量刷新结束后自动重新评估并触发事件 CAP 请求。
2. 自动恢复只在事件尚未完成、没有事件请求在途且数据渠道已配置时执行；请求失败仍落入统一友好错误态，用户可手动重试或去设置。
3. 该恢复规则与渠道/模型变更后的缓存清理保持一致，不复用旧渠道事件；桌面端、本地 Web 和普通浏览器预览共享同一状态语义。

验收：在行情批量刷新期间进入事件页不会出现无操作空白；行情刷新结束后事件请求自动启动；失败可重试；回归测试覆盖竞争窗口；Playwright 桌面/窄屏无控制台错误和水平溢出。

### 11.23 Stage 3G 消息中心筛选与可恢复操作（本轮增量）

将站内消息从单纯的结果列表升级为可定位、可恢复的工作入口。消息中心仍只展示真实数据流程产生的消息，不新增模拟通知或投资结论。

1. 消息卡片保留盯盘、组合提醒和其它消息类型，并显示未读状态、严重级别、数据来源、标的和消息时间；未读总数与左侧导航保持同步。
2. 支持按全部/未读/关键/提醒/信息筛选，支持按盯盘/组合提醒筛选，并可搜索标题、正文、标的、名称和来源；筛选无结果时提供清除入口，不删除原始消息。
3. 消息卡片具备键盘可访问的已读操作；“全部标为已读”只更新本地消息状态并持久化，不触发数据请求或系统通知。
4. 带标的上下文的消息提供“查看标的”，回到行情工作区并选中对应标的；盯盘消息额外提供“查看盯盘”。跳转动作先标记已读，不能因为筛选或跳转丢失消息。
5. 新产生的盯盘和组合提醒写入脱敏的 `symbol`、`name`、`ruleId` 上下文；用户状态备份兼容旧消息，API Key、模型配置、原始响应和提示词仍不会写入。
6. 桌面端和本地 Web 共用筛选与操作状态；窄屏下工具栏纵向排列，消息卡片和操作按钮不产生水平滚动。

验收：可在消息中心搜索和筛选真实消息；未读计数、单条/批量已读状态正确持久化；从消息可回到标的或盯盘页；旧版消息仍能正常展示；桌面/窄屏 Playwright 无控制台错误和水平溢出。

### 11.24 Stage 3H 自选工作台分组与排序（本轮增量）

参考 TradingView 的 watchlist 分组/排序和 Koyfin 的统一列表管理方式，将“自选”从不可组织的平铺列表升级为用户可快速分组、筛选和比较的入口；本阶段只改变本地组织方式，不改变真实数据获取契约。

1. 每个自选标的保存一个脱敏的 `group` 字段。旧数据没有分组时按市场迁移到 A 股、美股、港股或自选；自定义分组名称最多 64 个字符，不能覆盖标的代码或名称。
2. 侧边栏按分组渲染标的并显示组内数量；支持“全部/指定分组”筛选和“自定义顺序/名称/最新价/涨跌幅”排序。价格和涨跌幅排序只使用当前已收到的真实行情，缺失值始终排在末尾，不显示估算值。
3. 添加自选时可选择已有分组或新建分组；选择推荐标的和手动输入都必须写入同一分组字段。删除标的后不残留空分组，至少保留一个自选的约束继续有效。
4. 分组字段进入用户状态备份和恢复，兼容旧版备份；不写入 API Key、模型设置、缓存、原始行情或运行日志。切换数据渠道不会改变分组和排序语义。
5. 桌面端与本地 Web 共用分组和排序组件；控件具备标签和键盘焦点，筛选无结果显示明确空态，窄屏不产生水平滚动。

验收：默认自选按市场分组展示；切换分组只改变可见标的；名称/最新价/涨跌幅排序稳定且缺失行情保持为空；添加标的可新建分组并在刷新后保留；备份恢复保留分组；桌面/窄屏 Playwright 无控制台错误和水平溢出。

### 11.25 Stage 3I 事件日历持仓关联筛选（本轮增量）

补齐 F5-02 的第一步，让用户在事件日历中快速聚焦自己真正承担风险的标的。该筛选只改变客户端展示范围，不扩大数据请求范围，也不把自选事件误称为持仓事件。

1. 事件日历新增“全部自选 / 只看持仓”关联范围筛选；默认保持全部自选，切换后只展示当前持仓代码匹配的真实事件。
2. 匹配使用规范化证券代码（忽略 A 股 `.SH/.SS/.SZ` 后缀），不依赖名称，避免同名公司或市场后缀差异造成漏筛。
3. 没有持仓时选择“只看持仓”显示可恢复空状态，并提供“去组合”入口；不会显示“暂无事件”造成误解。已有持仓但没有匹配事件时，说明筛选范围并保留重置关联范围的路径。
4. 列表和月视图共享同一关联筛选结果；切换月份、关键词或未来/全部/已发生范围不会绕过持仓约束。
5. 事件页同时提供按自选标的已有 `category` 的行业筛选；它只筛选当前已返回的事件，不把行业分类扩展成未验证的全市场数据。
6. 桌面端与本地 Web 共用筛选状态和文案；不新增 API Key、行情缓存或事件结果持久化字段。

验收：持仓筛选只显示持仓标的事件；A 股代码带交易所后缀时仍可匹配；行业筛选只显示对应自选分类；无持仓显示“去组合”空态；列表/月视图结果一致；无真实事件时不生成占位日期；桌面/窄屏 Playwright 无控制台错误和水平溢出。

### 11.26 Stage 3J 桌面与 Web 用户状态契约一致性（本轮增量）

补齐桌面 Tauri Host 与本地 Web Host 的用户状态 schema，避免 Web 已支持的状态在桌面重启或保存时被静默丢弃。本阶段只处理脱敏用户事实，不把凭证、模型配置、缓存或运行日志写入 `user-state.json`。

1. 桌面端与 Web 共用以下持久化字段：自选分组 `watchlist[].group`；盯盘条件组合 `monitorRules[].conditions` 与 `logic`；消息的标的、名称、规则和事件提醒上下文；持仓止盈/止损、计划状态、周期、逻辑和操作记录；盯盘检查历史、条件结果及脱敏调用审计。
2. Tauri schema 对新增字段提供向后兼容默认值：旧版自选缺少分组时按市场迁移为 A 股、美股、港股或“自选”，旧版规则缺少条件组合时使用空条件和 `AND`，旧版没有检查历史时使用空列表；未知字段继续被忽略，但已纳入产品契约的字段不得被忽略或覆盖。
3. 桌面保存前执行与 Web Host 等价的集合规模、文本、价格、逻辑和计划字段校验；检查历史最多保留 500 条，每条最多 6 条条件结果、12 条审计，避免异常状态撑爆本地文件。
4. 事件提醒上下文字段进入白名单备份，仍不导出 API Key、模型网关、提示词、原始响应或运行日志；导入和桌面重启后应保持与 Web 相同的筛选、消息跳转和盯盘时间线语义。

验收：在本地 Web 创建分组、组合条件、持仓计划和盯盘检查记录后，桌面加载/保存/重启不丢失这些字段；旧版 `user-state.json` 可正常读取并获得安全默认值；超限或非法状态被友好拒绝；前端单元测试、构建和 Rust 格式检查通过，桌面原生依赖由 CI 平台构建验证。

### 11.27 Stage 1C 详细设计：用户状态契约硬化（本轮增量）

Web 本地 Host、浏览器回退和桌面 Host 必须在同一个脱敏状态契约上工作，不能因为传输层不同而出现“桌面可恢复、Web 显示异常”或把运行时字段写入备份的问题。本阶段作为下一版本的质量补丁，不改变页面功能和数据渠道。

交付内容：

1. 提取纯 JavaScript 状态归一化模块，统一限制自选、规则、通知、持仓计划和盯盘审计的字段长度、集合大小和枚举值；旧字段名继续兼容迁移。
2. 用户状态在读取和保存前均归一化；localhost Host 的 GET/POST 也执行同一归一化，并拒绝保存空自选，保证 Web 与 Tauri 的边界行为一致。
3. 归一化只保留用户状态白名单字段，API Key、模型配置、提示词和开发日志无法通过状态接口或备份外泄。

验收标准：

- 同一份合法状态在 Web、浏览器回退和桌面端读取后字段一致；
- 含超长文本、非法枚举、旧蛇形字段或运行时秘密的输入会被裁剪/丢弃，不阻塞其它合法数据恢复；
- 空自选状态不能被 Host 持久化；
- 单元测试覆盖字段边界、旧字段迁移、秘密剔除和备份往返；
- 不引入示例行情、不改变 QVeris CAP 对外契约。

### 11.28 Stage 1D 详细设计：真实数据短时复用与 CAP 响应校验（本轮增量）

在固定 `qveris_finance` CAP 工具的基础上，减少同一页面刷新、盯盘检查和详情面板在短时间内重复访问上游造成的等待。缓存只保存当前进程内、已经由 CAP 返回并通过 schema 校验的真实结果，不落盘、不跨渠道复用，也不以缓存替代定时刷新。

1. Host 按数据类型和完整参数生成隔离的内存缓存键：实时行情 15 秒、历史序列/资金流/新闻 60 秒、公司资料/事件 5 分钟；凭证、provider、CAP 地址或设置变化时立即清空。缓存命中记录为 `cap-cache-hit`，开发面板可看到命中与耗时。
2. CAP 明确返回 `success=false` 或 `status_code >= 400` 时统一判为不可用，不把响应中残留的部分字段展示给用户；空数组继续保持为空态，不能转成“未触发”或示例数据。
3. 能力目录只在 schema、provider 或渠道元数据变化时写盘，保留首次创建时间，避免每次行情请求都产生无意义的配置文件写入。
4. 对外 `foliomind_data` 和 `/api/data/query` 契约保持不变，新增 `dataCacheHit` 仅用于调试和性能观测；缓存命中、上游调用和回退行为均写入脱敏日志。

验收标准：

- 同一标的在 TTL 内重复请求不再产生第二次上游 CAP 调用，返回仍带真实来源与数据时间；超过 TTL 或设置变化后重新取数。
- 显式失败 envelope 不会进入行情、详情、事件、资金流或新闻页面；页面展示统一空态/友好重试入口。
- 能力目录的重复读取不会反复改写文件；目录版本或渠道变化时仍能更新。
- 单元测试覆盖失败 envelope、缓存命中日志和清理；`npm test`、构建及本地 Web Playwright 烟测通过。

### 11.29 Stage 1E 详细设计：市场异动雷达（本轮增量）

将 F2 的第一阶段交付前置到行情首页：在不增加模型调用和数据编造的前提下，基于已经返回的真实报价做可解释的价格/量能异常识别，让用户打开产品即可知道“现在是否值得关注”。

1. 异动检测在客户端纯计算完成，默认阈值为涨跌幅绝对值 ≥ 4%、量比 ≥ 2.5 倍；只有同时存在真实最新价和对应字段时才生成记录，缺失字段保持空态，不使用历史均值或模拟数据补齐。
2. 异动卡片展示标的、异常类型、实际数值、阈值、数据来源和数据时间；按高关注/需关注排序，不输出原因归因或交易建议。AI 归因仍由后续 RAG 阶段单独触发，避免把规则命中误称为因果结论。
3. 市场行情页新增“异动雷达”区域；无异动时明确显示“当前没有符合条件的异动”，部分行情返回时只基于已返回标的计算，并保留统一刷新入口。
4. 所有异动文案附“不构成投资建议”声明。桌面端与本地 Web 共用同一纯函数和组件，窄屏使用自适应卡片，不产生水平滚动。

验收标准：真实报价包含阈值字段时出现对应异动卡片；缺少涨跌幅/量比时不产生估算异动；排序和阈值文案稳定；空态、部分数据和刷新状态可恢复；单元测试、构建及 Playwright 桌面/窄屏检查通过。

### 11.30 Stage 1F 详细设计：CAP 能力浏览、调用测试与安装升级体验（本轮增量）

1. 开发面板扩展为本地能力工作台：展示当前已内置的 CAP tool schema（tool ID、能力 ID、用途、参数和返回字段），支持对每项能力用测试标的发起真实调用；测试结果只写入脱敏调用日志，未来 Skill 可复用同一稳定 schema，不直接暴露 API Key。
2. 能力列表明确区分“FolioMind 已固化可调用能力”和 Provider 的总能力数；未固化能力不伪装成已可用工具，后续通过目录版本和验证流程逐项纳入。
3. 开发面板默认更大的可视区域和更高字号，调用记录可展开查看接口、脱敏参数、返回摘要、费用和失败原因，并支持一键清空日志与成本统计。
4. Windows NSIS/MSI 更新沿用稳定 UpgradeCode 与 current-user 安装模式。同一产品旧版本执行覆盖升级，不要求用户先卸载或重复确认；只有无法判定为同一产品的安装才保留系统安装器的安全提示。用户配置、凭据和状态位于安装目录之外，升级不删除。

验收标准：开发面板能列出所有当前内置 CAP 并显示完整 schema，可输入测试标的；配置凭据后任一能力可在 Web Host 或桌面 Tool Runtime 发起调用测试，并在日志中看到真实返回或可解释错误；清理后日志和费用归零；桌面/Web 视图不横向溢出；Windows 构建保持稳定 UpgradeCode、禁止降级，且同一产品升级路径不触发手动卸载流程。

### 11.31 Stage 1G 详细设计：Local Host 公开契约可靠性门禁（本轮增量）

本地 Web 是桌面问题的快速调试入口，不能只用内部纯函数测试推断真实 HTTP 行为。本阶段启动隔离的真实 Host 进程和本机 mock 模型网关，对浏览器实际消费的公开路由做无外网端到端回归。

1. Host 支持监听动态回环端口并报告操作系统实际分配的端口，测试数据只写入独立临时目录，不读取或覆盖用户配置。
2. 未携带本轮 `X-FolioMind-Host` 会话令牌的配置、凭据、用户状态和 Runtime 请求必须返回 401；API Key 只能以脱敏前缀返回，不能出现在状态响应中。
3. 凭据状态、自选和自动复盘设置必须能跨 Host 重启恢复，且仍经过统一用户状态 schema 归一化。
4. 同一 Host 同时只接受一个模型分析请求；第二个请求返回 409。取消必须只终止当前 owner，释放互斥状态并恢复 `stopped`，不能让旧请求清理新请求状态。
5. 历史序列数据时间只从可解析的 date/time/timestamp 中选择最新值；混入 `unknown` 等非日期标签时不能把它误报为最新数据时间。

验收标准：集成测试真实经过 `/api/session`、鉴权、凭据、设置、用户状态、prompt、abort 和开发面板状态路由；全部上游由本机 mock 提供，不访问真实 QVeris、不消耗额度；测试结束必须回收子进程、监听端口和临时目录。该门禁纳入默认 `npm test` 和 GitHub 桌面/发布 workflow。

### 11.32 Stage 3K 自选批量导入与导出（本轮增量）

参考 TradingView 的 watchlist 文件导入/导出习惯，为首次使用和跨工具迁移补齐可恢复的自选管理入口。该阶段只处理用户自选事实，不请求行情、不写入凭证或运行日志；支持 FolioMind CSV 和常见的交易所前缀 TXT 列表。

1. 自选侧栏“更多”提供导入和导出操作。导出字段仅包含代码、名称、市场、分类和分组，不包含实时价格、API Key、模型配置或其它运行时信息。
2. 导入解析支持 UTF-8 CSV（可含中文表头、引号和逗号）及逐行 `NASDAQ:AAPL`、`SSE:600519` 格式；交易所前缀仅用于推断市场，页面和数据层继续使用 FolioMind 稳定代码契约。
3. 文件先完整解析和校验，再一次性写入用户状态；重复代码、格式错误和超过 200 个上限的行被逐条统计，不得出现导入一半后写入失败的不可恢复状态。
4. 成功、跳过和错误数量在侧栏给出反馈；没有可导入新标的时保持原列表不变并提示原因。导入后选中首个新增标的，分组沿用文件值或市场迁移规则。
5. Web 和桌面共用同一解析、归一化和持久化契约；窄屏菜单可操作且不产生水平溢出。导出文件可再次导入并保持分组和名称。

验收标准：导出的 FolioMind CSV 可无损导回；TradingView 风格 TXT 能识别交易所并推断市场；重复/非法行不会污染原状态；导入上限和 2 MB 文件限制生效；导入成功后状态持久化、刷新仍保留；单元测试、UI 测试、构建和 Playwright 窄屏检查通过。

### 11.33 Stage 3L 组合盘后复盘快照（本轮增量）

补齐 F3-03 的第一个可独立验收闭环：用户可以把当前组合的真实行情和已返回事件保存为可回顾的盘后复盘，不等待完整 AI 简报、服务端交易日历或后台调度上线。

1. 复盘只消费当前客户端已经收到的持仓真实行情，记录行情覆盖数、总成本、已计价市值、未实现盈亏、表现最好/最弱持仓、数据来源和截至时间；没有任何真实持仓行情时禁止生成。
2. 未计价持仓保留在覆盖率分母，但不进入市值、盈亏、排名或来源统计；不使用成本价、前收或样例数据代替现价。
3. 复盘同时保存当前可解释的组合风险信号，以及未来 7 天内已经由公司事件 CAP 返回且与持仓代码匹配的事件；没有事件时明确保持空状态，不推测日程。
4. 每份记录附“不构成投资建议或交易指令”声明；最多保留 90 份，可展开查看和单条删除，并随 Web/桌面用户状态及备份迁移。
5. 快照 schema 只允许结构化持仓表现、来源和事件摘要，不保存 API Key、模型配置、提示词、原始响应或开发日志。桌面 Rust Host 对集合数量、文本和数值再次校验。
6. 本阶段不宣称完成 F3-01 的交易日历调度或 F3-02 的 AI 盘前简报；后续在服务端日历和通知基础设施具备后，再增加 08:00/15:30 自动生成与失败重试。

验收标准：至少一笔持仓有真实现价时可生成并展开复盘；部分行情只计算已计价部分；无真实行情时给出可恢复提示；真实来源、截至时间、风险和事件可追溯；删除、备份恢复与桌面重启保持一致；单元测试、构建和 Playwright 桌面/窄屏验证通过。

### 11.34 Stage 3M 本地自动盘后复盘调度（本轮增量）

参考 TradingView 的提醒频率/状态管理和 Koyfin 的组合提醒/通知中心，将手动复盘扩展为可解释、可恢复的本地调度闭环，但不把前端定时器包装成服务端任务。

1. 用户可在组合页启用自动复盘并配置北京时间执行时刻，默认工作日 15:35；调度配置、最近尝试、最近成功键、结果和友好错误随 Web/桌面状态持久化及备份迁移。
2. 每个自然日使用 `close:<YYYY-MM-DD>` 幂等键；启动、每分钟、窗口聚焦和页面恢复可见时 reconcile，同一天已有手动或自动复盘即视为完成，避免 StrictMode、刷新和重复 focus 生成多份记录。
3. 到点后先刷新真实行情；只有至少一个持仓报价的数据日期与北京时间当天一致才生成复盘。无凭据、无持仓、周末、未到点、数据陈旧或空返回均不生成数字，也不使用成本价或昨日收盘替代。
4. 无当日行情或可恢复错误按 5–60 分钟的有界间隔重试；状态明确显示等待数据、成功或失败。成功后先持久化复盘与站内消息，再尝试系统通知，通知失败不回滚已生成记录。
5. 本阶段明确限定“应用运行期间执行”。周一至周五只是保守候选日，不等同真实交易所日历；Web 页面关闭和桌面应用完全退出后不会运行。后续需接入分市场交易日历 CAP 与桌面后台 worker，才可升级为 08:00/15:30 的生产级跨市场简报服务。

验收标准：跨系统时区仍按 Asia/Shanghai 判定；周末/未到点不执行；同日手动记录、重复轮询和重启不会重复；陈旧/缺失行情保持等待并节流重试；当日真实行情生成一份记录和一条消息；状态可备份恢复；桌面/Web 和窄屏无溢出；单元、Rust、构建和 Playwright 回归通过。

### 11.35 Stage 3N 真实交易日历门禁（本轮增量）

将自动盘后复盘从“周一至周五候选日”升级为真实交易所日历判断。QVeris 目录已通过 Search、Inspect 和 Call 实测验证 `cn_financial_pro.trade_dates.v1`，稳定能力为 `REF.EXCHANGE_CALENDAR`；当前先覆盖上交所日历，后续按组合市场拆分。

1. Web Host 与桌面 Host 直接调用固定交易日历 CAP，不经过模型，不使用公司事件或宏观日历替代。请求仅包含市场代码和目标日期，返回稳定的 `isTradingDay/tradingDates/source/toolId/capability` 契约。
2. 调度到点后必须先取得目标日期的明确日历结果；交易日才进入真实行情门禁，休市日记录 `market-closed` 并停止。日历失败或结构异常进入 `waiting-calendar`，不得按工作日猜测，也不得生成复盘。
3. 日历结果按日期持久化到脱敏调度状态；Local Host 的已验证结果可在进程内缓存 12 小时，配置、凭据或渠道变化时立即失效，避免反复产生 2 credits 调用费用。
4. UI 显示核验日期、交易/休市状态和数据来源；开发面板列出该 CAP 的 tool ID、参数、返回字段和调用测试。休市原因、半日市与交易时段未由当前返回结构证明，不在界面中推测。
5. 桌面调用使用 Host 凭据存储和受限参数；API Key、原始响应和查询费用不写入用户状态。408/425/429/5xx 仅有限重试，401/403 立即返回友好权限错误。
6. 本阶段仍明确限定应用运行期间执行。关闭窗口后继续运行、托盘、登录启动和状态 revision 属于下一后台 Worker 阶段，不能因接入真实日历而宣称已经支持完全后台调度。

验收标准：真实 CAP 可确认交易日与休市日；同一日期调度不会重复查询；日历失败时 fail closed；交易日仍必须具备当日真实持仓行情才生成；Web 与桌面返回同一稳定 schema；单元测试覆盖交易、休市、结构异常、同 owner 状态推进和状态迁移，Windows/macOS 原生 CI 通过。

### 11.36 Stage 3O 桌面驻留生命周期（本轮增量）

把桌面端从“关闭主窗口即退出”升级为明确的系统托盘驻留模式，为生产级后台 Worker 建立可靠的进程生命周期。此阶段不改变 Web 的能力边界，也不把隐藏 WebView 宣称为完全原生后台服务。

1. 用户点击主窗口关闭按钮时阻止销毁窗口并隐藏到系统托盘；最小化、隐藏或恢复窗口不得终止 Host、Pi runtime 或已启用的自动复盘协调器。
2. 托盘菜单必须提供“显示 FolioMind”“立即检查盘后复盘”“退出 FolioMind”。只有显式退出才停止进程；Linux 不依赖托盘单击事件，三项操作必须全部在菜单中可达。
3. Rust 驻留 ticker 每 60 秒向仍存活的桌面 WebView 发出一次复盘 reconcile 事件，托盘“立即检查”使用同一事件；前端继续复用真实交易日历、当日行情和同日幂等门禁，不新增第二套业务判断。
4. 显式退出先停止并回收 ticker，再关闭 Local Web Host 和 Pi 子进程。`ExitRequested` 与 `Exit` 可能连续到达，清理必须只执行一次，避免重复 join 或残留子进程。
5. 设置页应明确说明桌面驻留和 Web 页面关闭后的差异。桌面命令暴露只读状态与立即检查，不向用户状态、日志或前端传递 API Key。
6. 本阶段仍依赖存活 WebView 执行复盘业务逻辑；操作系统挂起渲染进程、登录启动、崩溃恢复和 Host 内原生行情/状态事务由下一阶段 `BackgroundScheduler` 完成。在该阶段完成前，不承诺窗口隐藏期间的硬实时执行或 exactly-once 上游调用。

验收标准：普通关闭走隐藏、显式退出走关闭；托盘三项菜单可编译并在 Windows/macOS 安装包运行；ticker 与手动检查复用同一事件；退出清理幂等；Web 不出现桌面命令错误；设置页和组合页文案不夸大能力；单元、构建、架构和桌面原生 CI 通过。

### 11.37 Stage 3P 用户状态版本与后台写入并发控制（本轮增量）

为后续原生后台调度器持续写入提醒、复盘和检查历史建立安全持久化边界。当前 WebView、localhost 调试页和桌面后台任务可能同时持有用户状态，任何一方都不能用旧的完整快照覆盖另一方刚写入的数据。

1. 用户状态根对象增加单调递增 `revision`；旧文件无该字段时按 0 迁移，API Key、模型配置、缓存和日志仍不得进入用户状态。
2. Local Host 与桌面 Host 保存接口必须携带 `expectedRevision`，在同一文件锁或串行写队列内比较当前版本并原子写入；版本不一致返回可识别的 409 冲突，不得静默覆盖。
3. 客户端收到冲突后重新读取远端状态，以最近成功保存快照为基线做三方合并。不同自选、规则、消息、历史或复盘记录可安全合并；同一记录的相互冲突修改必须停止并提示用户刷新。
4. 浏览器调试、桌面和便携备份共用同一归一化契约；备份不携带 revision，导入后使用目标设备当前版本，避免跨设备伪造并发顺序。
5. 架构 Review 和真实 Local Host 集成测试持续检查 revision、冲突响应、重启恢复和过期写入拒绝，为下一阶段原生 `BackgroundScheduler` 提供门禁。

验收标准：两个客户端从同一 revision 保存时只有一个直接成功；另一个的无冲突修改可在重读后合并并产生下一 revision；同一记录的冲突修改不丢失任何一方数据；旧状态和旧备份可迁移；凭据不出现在状态或备份中；默认测试、构建、架构审查和发布 CI 全部通过。

### 11.38 Stage 3Q 原生后台复盘调度器（本轮增量）

将桌面端盘后复盘从 WebView 定时器迁移到 Rust `BackgroundScheduler`。桌面窗口隐藏、渲染进程被系统降频时，任务仍由桌面 Host 独立判断和执行；本地 Web 调试继续保留浏览器调度，两个运行形态不得同时成为同一任务的 owner。

1. 原生 worker 启动后及每分钟检查一次北京时间调度状态；托盘与组合页“立即检查”走同一原生入口。桌面前端不再运行盘后复盘定时器，只监听完成事件并重新读取持久化状态。
2. 到期任务先通过固定 `REF.EXCHANGE_CALENDAR` CAP fail closed 核对真实交易日，再直接调用固定 `MKT.L1.RT` CAP 获取持仓行情，不经过模型或 Discover。当前交易日门禁仍明确只覆盖上交所日历；跨市场组合调度需在后续按市场拆分，不能把北京时间门禁宣传成全球市场支持。
3. 只接受正数真实价格和目标交易日时间戳；缺价持仓不使用成本价或旧收盘替代。组合盈亏仅累加已计价持仓，数据来源、截至时间和覆盖数量随复盘保存；没有可用当日行情时保持等待并按 5–60 分钟间隔重试。
4. 网络请求在状态锁外执行。开始和结束均重新读取最新 revision，最终写入使用短事务；行情刷新期间持仓或 revision 发生变化时放弃旧快照。同一交易日已有复盘时不再次插入，也不重复发送站内或系统通知。
5. 单次任务设置连接/总超时并限制并发；退出只回收调度循环，不等待尚未结束的上游网络调用，避免安装升级或显式退出被长请求阻塞。任务成功后先原子保存复盘和站内通知，再尽力发送 Windows/macOS 系统通知，通知失败不回滚数据。
6. API Key 只从桌面凭据存储读取，原始响应、密钥和请求参数不写入用户状态。错误只持久化有界友好摘要；配置或凭据变化后沿用既有日历失效与重试机制。

验收标准：隐藏窗口后不依赖 WebView 仍可完成任务；桌面与 Web 不双调度；交易日历失败、休市、陈旧行情或空行情均不生成；重复触发、并发状态写入和重启只生成一份复盘及一条通知；部分行情口径与前端一致；退出不被慢请求长期阻塞；Rust 单元测试、前端测试、架构审查、Windows/macOS 原生 CI 与正式安装包构建全部通过。

### 11.39 Stage 3R 原生调度可观测性与成本账本（本轮增量）

将桌面后台任务纳入开发面板的统一排障与成本视图，解决窗口隐藏后无法判断“调用了什么、耗时多久、为何失败、扣了多少费”的问题。

1. `BackgroundScheduler` 对交易日历和实时行情 CAP 发出脱敏调用事件，至少包含时间、操作、稳定 tool ID、能力 ID、请求参数、HTTP 状态、耗时、返回摘要、失败原因和上游费用；原始响应、API Key、提示词和完整业务数据不得进入日志。
2. 桌面开发面板实时接收原生事件，与 Pi/模型网关事件统一展示接口、参数、返回摘要、失败原因和耗时，并支持清理日志。日志仅用于当前运行期调试，不作为用户状态或备份内容。
3. 成本账本按 CAP 与模型网关分别汇总调用次数和已返回费用。上游未提供可验证费用时显示“费用未知”，不得猜测或用固定单价替代；费用字段允许兼容 `qveris_cost`、`charged_credits`、`fee` 等网关变体。
4. 能力目录中的调用测试与后台事件使用同一 tool/capability 标识，后续可直接把已验证 CAP 暴露为 Skill 工具；渠道切换或模型更新后，日志和成本窗口立即按新运行上下文隔离。

验收标准：隐藏窗口执行一次真实调度时开发面板可见日历/行情调用、参数、返回摘要、耗时和失败原因；成功返回费用时可按 CAP/模型汇总，缺失费用明确标记未知；清理后不残留旧事件；日志不含密钥和完整原始响应；Rust 单元、前端测试、架构审查、Windows/macOS 原生 CI 与正式安装包构建全部通过。

### 11.40 Stage 3S 能力目录与多币种成本诊断（本轮增量）

将“已支持的 CAP”做成可验证的开发者工作台，确保开发者能在不阅读源码的情况下判断能力边界、参数契约、真实调用结果和费用口径。

1. 开发面板展示当前 provider 的能力总量、已验证能力数、版本和刷新入口；每项能力必须公开稳定 capability ID、tool ID、用途说明、参数 schema、返回字段和覆盖边界。未验证的上游能力只能显示总量，不得伪装成可调用工具。
2. 每项能力提供独立的真实调用测试，测试按钮不与可展开标题嵌套，结果以状态消息反馈，并将耗时、参数、返回摘要和失败原因写入同一调用日志；测试失败不得展示部分结果或猜测数据。
3. 成本账本分别按 CAP 与模型网关统计调用次数、已知费用和计费单位。不同调用类型或多币种费用不得复用同一个单位标签；部分调用未返回费用时显示已知/总调用数，未知费用不做估算。
4. 刷新能力目录后立即读取 Host 的最新目录和配置变化；清理日志同步重置费用窗口。密钥、原始提示词、完整响应和凭据仍不得进入日志或用户状态。

验收标准：能力目录可刷新且与 Host 契约一致；每项已验证 CAP 都能展开查看 schema 并独立发起调用测试；键盘操作不会误触发标题展开；CAP credits 与模型 USD 等不同单位分别显示；部分费用缺失时明确标注已知笔数；前端、Host 集成测试、构建和架构审查通过。

### 11.43 Stage 2D 异动证据解读（本轮增量）

5. 来源 URL 仅允许 HTTPS/HTTP；非法协议被丢弃。失败、超时、并发占用和无证据均提供可恢复重试，不阻塞行情卡和其它标的。

验收：真实异常可按需发起解读；Web/桌面分别能从固定 CAP 或 Pi 工具得到证据；诱因均可展开来源并显示数据时间；模型无来源的原因被过滤；持仓关系不泄露到备份/日志；无证据不猜测；失败可重试；单元测试、构建、架构审查和 1440px/390px Playwright 回归通过。

### 11.44 Stage 2E 动态自选组盯盘（本轮增量）

参考成熟行情产品的 Watchlist Alert 交互，将盯盘规则从单标的扩展为可跟随自选变化的动态范围，同时保持每个标的独立判定和提醒去重。

1. 新建盯盘时可选择“单个标的”或“整个自选”。自选组规则只保存范围标识与条件，不复制当时的标的列表；以后加入或移除自选会自动影响下一次检查。
2. 自选组检查按受限并发逐标的执行固定 CAP/真实数据链路；一个标的失败不阻塞其它标的，结果分别写入审计时间线，并以一次汇总消息提示失败数量和可恢复原因。
3. 触发边沿按标的维护，持续满足条件不重复通知；某个标的恢复后再次触发才生成新通知。历史记录必须包含实际标的代码，不能把整组结果混成一条无法追溯的结论。

5. 浏览器预览不执行真实检查；没有凭据、没有自选或数据字段缺失时保持待核实/空态，不生成假触发。桌面与 Local Host 使用同一契约和通知去重逻辑。

验收：可以创建动态自选组规则并在列表中明确显示；真实检查覆盖当前全部自选，部分失败不影响成功标的；同一标的重复触发不刷屏且恢复后可再次提醒；新增/删除自选无需编辑规则即可生效；备份导入导出保留范围和去重状态；单元测试、构建、架构审查和 1440px/390px Playwright 回归通过。

### 11.49 Stage 3Z CAP 到 Skill Tool 的契约导出（本轮增量）

验收：8 项已验证 CAP 均可导出合法、可解析的 function tool schema；必填/可选参数和稳定 tool ID 保持正确；Web/桌面按钮可用且不改变真实数据调用；前端测试、构建和架构审查通过。

### 11.50 Stage 3AA 动态 CAP 能力目录（本轮增量）

1. 本地 Web Host 提供“加载完整目录”入口，默认查询 `provider:qveris_finance`，最多展示上游返回的 100 项；用户可以输入其它能力级查询词，Search ID 与更新时间可追溯。

### 11.51 Stage 3AB 事件日历双重提醒（本轮增量）

将事件日历从“被动查看”推进为可恢复的提醒入口，补齐 F5-03 的第一版闭环。提醒只消费当前刷新成功的真实公司事件，不把未知日期或模型推测变成通知。

1. 事件日期按北京时间的自然日解释；事件距离今天 1–7 天时生成一次“提前提醒”，事件当天再生成一次“事件今日提醒”。如果用户错过精确的第 7 天刷新，只要在 7 天窗口内首次成功刷新，仍会得到一次可追溯的提前提醒。
2. 每条提醒以 `eventKey + reminderPhase` 幂等去重。`eventKey` 由规范化标的、日期、事件类型和标题组成；同一事件标题被真实数据源修订时视为新版本，保留新的来源和提醒记录，旧通知不被覆盖。
3. 提醒写入现有站内消息和用户状态脱敏 schema；字段包含标的、日期、类型、来源、数据服务标识和“不构成投资建议”声明，不写入 API Key、原始响应或提示词。系统通知仍遵循用户主动授权，权限拒绝不影响站内留痕。
4. 消息中心增加“事件提醒”筛选和类型标签，点击“查看标的”回到对应行情工作区；提醒失败不会阻塞事件列表刷新，未知/无日期事件保持可查看但不触发通知。

验收：真实事件在 7 天窗口内刷新一次生成一条提前提醒；同一事件当天再生成一条当天提醒；重复刷新不新增；日期解析不受浏览器时区影响；空日期、过去事件和无真实事件不生成提醒；站内筛选、标的跳转、备份恢复和系统通知行为与现有消息契约一致。

### 11.52 Stage 3AC 费用与时区口径修复（本轮增量）

修复桌面原生审计与 Local Host 使用不同费用结构，以及后台复盘按字符串截取时间导致 UTC 边界误判的问题，确保开发面板和复盘门禁与真实上游返回保持一致。

1. 开发面板统一接受 `{amount, unit}`、原生审计的 `cost + costUnit` 和兼容网关的数值费用字段；CAP credits、模型网关 USD 等单位分别汇总，未返回费用仍标记未知，不做估算。
2. 桌面 Pi/CAP 审计事件和后台调度事件使用同一费用归一化逻辑，调用次数、已知费用笔数、单位和总额均可追溯；清理日志后统计窗口归零。
3. 后台复盘判断行情是否属于交易日时，优先解析 RFC3339 偏移并转换为北京时间自然日；无法解析的日期字符串才使用兼容的日期前缀，缺失时间仍按不新鲜处理。
4. 费用和日期修复不得改变行情、复盘或凭据 schema；不将原始响应、API Key、提示词或推断费用写入用户状态。

验收：桌面原生数值费用能在开发面板显示正确金额和单位；混合 CAP/模型单位不会合并；未知费用显示已知笔数；UTC 跨日时间戳按北京时间正确判断；前端单测、Rust 单测、架构审查、构建和正式安装包流程通过。

### 11.53 Stage 3AD 数据访问与模型访问解耦（本轮增量）

将真实金融数据与 Agent 对话视为两条独立能力链路，避免用户已保存 API Key 仍因尚未选择模型而无法查看行情、事件、公司资料或盯盘结果。

1. CAP 数据访问只要求有效的 QVeris API Key 和合法数据渠道配置；行情、自选自动刷新、详情、历史序列、公司事件、资金流、新闻和盯盘不得以模型选择作为前置条件。
2. 模型访问仍要求 API Key、已同步模型目录和有效模型 ID；对话、异动 AI 解读及其它需要模型推理的功能在未选模型时保持明确的设置提示，不回退到假数据。
3. Web 与桌面页面共用同一访问状态语义：真实数据状态只反映 CAP 凭据，模型状态单独展示；保存或清除凭据、切换数据渠道时清理对应缓存和错误，避免旧结果跨渠道残留。
4. 空态文案需说明“保存 API Key 即可查看真实数据；同步模型后可使用 Agent 对话”，不得把模型网关错误误报为行情渠道错误。

验收：仅保存 API Key、未选择模型时，Web/桌面可调用固定 CAP 并展示真实行情或真实空态；对话和 AI 解读仍被模型门禁保护；清除凭据后所有 CAP 页面回到未配置态；前端单元、Host 集成、桌面 CI、构建和架构审查通过。

### 11.54 Stage 3AE 桌面固定 CAP 数据通道（本轮增量）

补齐 Stage 3AD 的桌面实现：桌面行情页面不能因为 Pi 未选择模型而失去真实数据能力。桌面 Host 直接调用已验证的固定 CAP，和 Local Host 使用同一类稳定返回契约。

1. 桌面 Host 提供受限 `qveris_data_query` 命令，仅允许内置的 quote、details、fundamentals、series、core_event、capital_flow、sentiment 能力；tool ID 与参数由应用内白名单生成，不接受任意 URL 或任意工具透传。
2. 每次请求从系统凭据存储读取 API Key，使用配置中的能力网关地址，通过 HTTPS、短连接超时和有限瞬时错误重试执行；401/403、空结果和结构异常均返回友好的可恢复错误。
3. 返回数据统一为 `data/mode/cacheHit/audits/toolId/capability` 契约；详情请求可以补充估值指标，但补充失败不得伪造指标。CAP 原始响应、API Key 和完整业务数据不写入日志或用户状态。
4. 桌面端行情、详情、历史序列、事件、资金流、新闻和盯盘复用该通道；开发面板接收同一脱敏调用审计，显示接口、参数、状态、耗时、返回摘要和已返回费用。
5. 固定 CAP 仍可作为后续 Skill Tool 的来源；动态能力目录只用于查看和验证，不改变白名单安全边界。模型网关继续只服务于对话和 AI 解读。

验收：桌面仅配置 API Key、未选择模型时可成功调用固定 CAP 或显示真实空态；桌面与 Local Host 的解析结果一致；无效凭据、超时、空响应和网关错误均可恢复；开发面板可看到脱敏审计与费用；Rust/前端单测、构建、架构审查和正式安装包流程通过。

### 11.55 Stage 3AF CAP 能力工作台检索（本轮增量）

能力目录从少量固化工具扩展到实时 provider 目录后，开发者可能需要在几十到上百个条目中快速定位目标能力。本阶段只优化开发工作台的本地检索，不改变能力验证、调用或 Skill 暴露边界。

1. “当前支持的金融能力”提供本地即时筛选，匹配稳定 capability ID、tool ID、能力用途、kind 和 provider；筛选不发起网络请求，也不改变 CAP 参数、缓存或调用日志。
2. 筛选结果显示“当前显示数/已固化数”，无匹配时显示可操作的空态，并保留清除输入即可恢复全部能力的路径。
3. 动态发现目录仍单独展示，继续明确区分“已固化可调用能力”和“仅供查看/验证的 provider 能力”，避免筛选结果把未验证工具误认为产品已支持。

验收：输入 capability ID、tool ID 或用途关键词后列表即时收敛；无匹配有明确空态；清除关键词恢复完整固化列表；动态目录项不重复出现在固化列表；键盘操作、桌面和 390px 窄屏无横向溢出，前端测试、构建和架构审查通过。

### 11.56 Stage 3AG 自选市场宽度概览（本轮增量）

参考 TradingView Watchlist Advanced View 的列表汇总能力，为市场页补充当前自选的可解释市场宽度，帮助用户在打开页面后快速判断上涨/下跌分布和极值标的。该阶段只消费当前已返回的真实行情，不新增上游请求。

1. 市场页展示上涨、下跌、平盘数量，以及最大涨幅和最大跌幅对应的标的；每项都标明统计范围，无法比较时显示“—”。
2. 统计只纳入同时具有有效正数价格的行情；涨跌幅缺失的标的不计入上涨/下跌/平盘，也不参与极值比较。缺失标的数量需明确提示并沿用现有定时刷新。
3. 统计与列视图、异常雷达共享同一 `liveQuotes` 内存数据，不改变 CAP 参数、缓存键、Provider 或用户状态；不使用预览行情、旧值或推算值填充。
4. Web 与桌面共用组件；窄屏下概览卡片可换行，不能产生页面级横向溢出；辅助说明应能被屏幕阅读器读取。

验收标准：真实行情返回后市场宽度正确显示并随刷新更新；缺失价格/涨跌幅保持空值且不改变统计口径；极值并列结果稳定；未配置凭据或无真实行情时不显示假汇总；1440px/390px Playwright 无控制台错误和水平溢出；单元测试、构建和架构审查通过。

### 11.57 Stage 3AH 设置页真实数据连接诊断（本轮增量）

针对首次配置时“API Key 看似已保存但不知道是否真的可用”的高频排障路径，在设置页增加一次显式、低成本的真实 CAP 探针。探针不依赖模型，不改变默认行情刷新，也不把测试结果写入用户状态。

1. 保存数据服务 API Key 后显示“测试数据连接”按钮，使用当前自选中的第一个标的（没有自选时使用 `600519`）调用固定 `quote` CAP；未配置凭据、浏览器预览或数据能力地址尚未保存时按钮禁用并说明下一步。
2. 成功必须确认返回有效正数价格，并展示标的、返回来源、数据时间/未知时间和请求耗时；不得把 HTTP 成功但无可识别行情的响应判为成功。
3. 失败只显示统一友好文案，不泄露 API Key、完整响应或内部堆栈；调用详情沿用开发面板的脱敏审计日志，用户可重试。
4. 测试只验证已保存的数据能力配置；用户修改地址后必须先“保存并应用”，避免探针结果与实际行情链路不一致。该探针不要求同步模型，明确体现 CAP 数据与模型访问解耦。
5. Web 本地 Host 和桌面端复用 `queryCapabilityData` 稳定契约；窄屏下状态文案可换行且按钮仍可操作。

验收标准：仅保存 API Key、未选择模型时可执行测试并得到真实成功或真实空/失败态；成功结果包含来源、时间和耗时；无效响应不会误报成功；修改未保存地址时测试受阻并给出可操作提示；失败可再次测试；前端测试、构建、架构审查和 Playwright 设置页交互通过。

### 11.58 Stage 3AI 跨链路忙碌状态可见性（本轮增量）

行情批量刷新、盯盘检查和 Runtime 配置共用资源互斥门禁。此前对话输入框没有反映行情刷新门禁，用户点击发送后请求会被安全拒绝但看不到原因。本阶段把共享门禁状态同步到对话 UI，消除“点击无反应”的错觉。

1. 行情批量刷新期间，对话输入框、快捷指令和发送按钮均禁用；输入框提示“正在更新行情，完成后可发起分析…”，发送按钮提供可读的“等待行情更新”标签。
2. 行情刷新结束后控件自动恢复，不清除用户已经输入的草稿；其它 Runtime 配置、取消和盯盘忙碌状态继续保持原有优先级与文案。
3. 该改动只反映现有 store 门禁，不改变对话、CAP、缓存、取消或审计契约；普通浏览器预览和 Local Host/桌面共用同一 UI 语义。

验收标准：行情刷新期间不会产生静默发送；键盘和按钮均不可触发请求；完成刷新后草稿和发送能力恢复；既有配置/取消/盯盘状态文案不回归；前端测试、构建、Playwright 控件状态和架构审查通过。

### 11.59 Stage 3AJ CAP 测试结果真实性（本轮增量）

修复能力工作台把“HTTP 成功”误认为“能力可用”的边界。CAP 可能返回 2xx，但没有有效行情或任何可展示字段；开发者需要明确区分失败、成功和真实空结果，避免把空响应误判为可接入能力。

1. 能力测试先检查显式失败标志和嵌套状态码；失败结果显示可恢复错误，并引导展开脱敏调用日志查看原因。
2. 行情能力必须收到正数价格才显示“测试成功”；缺少价格、价格非法或 quotes 为空时显示“调用成功，但没有返回可识别的真实行情”。
3. 序列、事件、资金流、新闻和交易日历等能力在返回空集合时显示“调用成功但没有可展示数据”，不填充示例值，也不把空结果写入稳定能力缓存。
4. 可识别的真实响应仍展示成功状态并保留现有费用、来源和调用审计；测试状态只存在开发面板运行态，不改变产品页面数据。

验收标准：2xx 空响应不会显示误导性的“测试成功”；有效行情响应保持成功；显式失败和嵌套 4xx/5xx 保持错误；稳定与动态能力在 Web/桌面共用同一状态语义；前端测试、Host 测试、构建、架构审查和窄屏回归通过。

### 11.60 Stage 3AK 动态 CAP 参数试验台（本轮增量）

完整 provider 目录中的动态 CAP 往往需要标的之外的周期、日期或筛选参数。仅使用自动生成的样例无法验证真实工具的边界，也无法复现一次失败调用。本阶段为动态能力增加受控的 JSON 参数编辑器。

1. 每个动态 CAP 展开后显示基于其参数 schema 生成的可编辑 JSON 样例；标的变化时，未被用户编辑过的样例可随之更新，用户已编辑的内容保持不变。
2. 点击“调用测试”前在本地解析 JSON，只接受对象（拒绝数组、空值和非法 JSON），长度受限；校验失败不发起网络请求，并显示可修复的参数提示。
3. 通过测试的参数原样传递给 Local Host 的 `tool_id/search_id/parameters` 契约；不改变稳定 CAP 白名单、缓存或用户状态，也不把完整参数写入持久化日志。
4. Web 与桌面能力目录继续保持只读发现和安全边界；动态 CAP 的自定义测试仅用于开发验证，不自动进入产品默认行情链路或 Skill 暴露列表。

验收标准：动态能力可编辑并发送自定义对象参数；非法 JSON/数组在本地被拒绝且不产生上游调用；样例参数仍能正常测试；窄屏下文本框可操作且无页面横向溢出；前端测试、构建、架构审查和正式安装包流程通过。

### 11.61 Stage 3AL 市场行情表格真实字段映射（本轮增量）

修复市场页自选表格的列定义与字段取值之间的映射错误。此前表头使用列对象，而取值函数按列 ID 判断，导致顶部行情卡与市场宽度已经有真实价格时，表格仍全部显示“—”，形成高风险的数据可信度断裂。

1. 表格渲染将列定义对象显式转换为列 ID，再交给统一 `marketColumnValue` 取值函数；最新价、涨跌幅、成交量、成交额、换手率、估值和数据时间沿用既有真实字段与空值规则。
2. 只修复显示层映射，不改变 CAP 请求、缓存、归一化、用户列偏好或数据来源；字段缺失仍显示“—”，禁止用其它字段推算填充。
3. Web 与桌面共用同一市场组件；真实行情表格必须与顶部行情卡、市场宽度使用同一 `liveQuotes` 结果，避免同一响应出现互相矛盾的展示。

验收标准：给定真实 quote 时表格正确显示价格、涨跌幅和估值字段；缺失字段保持空值；列设置和命名视图不回归；前端测试、构建、架构审查、桌面发布和窄屏回归通过。

### 11.62 Stage 3AM 涨跌方向缺失值中性化（本轮增量）

修复真实行情缺少涨跌幅时的视觉与筛选口径。此前部分卡片会因为默认比较行为显示下跌颜色，研究筛选也会把缺失涨跌幅归入上涨，容易让用户误以为渠道已经返回了方向信息。

1. 统一使用 `changeToneClass` 将正数标为上涨、负数标为下跌；零值和缺失/非法值均保持中性，不添加方向性颜色。
2. 研究筛选的“上涨/下跌”只接受有效的非零涨跌幅；缺失或非法涨跌幅不会被归入任一方向，仍可在“全部”中看到。
3. 该修复只改变展示和筛选边界，不改变真实行情、缓存、CAP 参数、市场宽度统计或用户状态；价格存在但涨跌幅缺失时，价格仍正常显示，涨跌幅显示空态。

验收标准：缺失涨跌幅的行情卡、详情页和自选表格不显示上涨/下跌颜色；研究筛选不会把缺失值列入上涨或下跌；正负数和零值保持正确口径；前端单测、构建、架构审查和窄屏回归通过。

### 11.63 Stage 3AN 研究筛选排序（本轮增量）

让研究页具备常用金融终端的快速比较能力，同时保持真实数据边界。

1. 研究结果支持按默认顺序、最新价、涨跌幅、市盈率、市净率排序，并可在升序/降序间切换。
2. 排序仅使用当前已返回的真实行情字段；字段缺失的标的始终排在末尾，不用 0 或示例值参与比较；并列值保持原自选顺序。
3. 排序与搜索、涨跌方向、仅显示有行情条件叠加；切换条件不会改变自选和行情原始状态。
4. 移动端工具栏允许换行，排序控件具备可访问标签；无排序时方向按钮禁用并保留明确状态。

验收标准：排序数值顺序、缺失值末尾、稳定并列顺序有单元测试；研究页桌面/窄屏交互通过浏览器回归；架构审查确认没有引入虚假数据。

### 11.64 Stage 3AO 组合分布真实权重（本轮增量）

补充上市级投资组合常见的暴露概览，让用户在查看盈亏前先理解市值集中在哪里。

1. 组合页展示每个已计价持仓的真实市值、占已计价组合的权重和比例条，并按权重从高到低排列；并列保持原持仓顺序。
2. 只有返回有效正数现价的持仓进入分布；缺少现价的持仓不参与分母、不显示估算条，并明确提示未计价数量。
3. 分布复用现有 `portfolioMetrics` 与 `liveQuotes`，不新增上游请求、不写入用户状态、不改变盈亏和风险信号口径。
4. 无持仓或暂无真实现价时显示可操作空态；桌面和窄屏布局均可阅读，比例条有辅助文字而非唯一信息载体。

验收标准：市值权重、缺失现价排除和稳定并列顺序有单元测试；组合页浏览器回归无控制台错误和页面横向溢出；构建、安全审计与架构审查通过。

### 11.65 Stage 3AP 持仓明细排序（本轮增量）

让组合页能够快速比较持仓暴露和表现，减少在长列表中手动查找的成本。

1. 持仓明细支持默认顺序、市值、未实现盈亏和组合占比排序，并可切换升序/降序；并列值保持原持仓顺序。
2. 排序只使用 `portfolioMetrics` 已计算的真实字段；缺失现价导致的市值、盈亏和占比为空时始终排在末尾，不用零值替代。
3. 排序只改变当前页面展示顺序，不修改持仓、提醒、交易计划或用户状态；刷新行情后排序结果随真实值重新计算。
4. 桌面和窄屏工具栏可操作且无页面横向溢出，排序控件有可访问名称。

验收标准：数值顺序、缺失值末尾、稳定并列顺序有单元测试；组合页桌面/窄屏浏览器回归、构建、安全审计和架构审查通过。

### 11.66 Stage 3AQ 组合价格正值门禁（本轮增量）

强化组合数据可信度，防止上游异常值进入市值、盈亏、权重和价格提醒。

1. 组合计算只接受严格大于 0 的现价；零值、负数、空值和非法值均按缺失真实行情处理。
2. 无效现价不会生成市值、未实现盈亏、组合占比或止盈/止损触发，原始持仓事实仍保留。
3. 该门禁复用所有组合计算路径，不改变 CAP 请求、缓存、用户状态或报告字段结构；缺失值继续显示为空态。

验收标准：组合指标、分布、提醒和导出对零/负数价格保持空值；正数行情行为不回归；单元测试、构建、架构审查和窄屏回归通过。

### 11.67 Stage 3AR 市场表格详情快捷打开（本轮增量）

### 11.78 Stage 3BC 用户状态加载失败可恢复与早期编辑保护（本轮增量）

1. 用户状态读取失败时保持 `userStateLoaded=false`，停止行情刷新、盯盘和盘后复盘等依赖持久化状态的后台任务；页面显示统一、脱敏的错误和“重新读取本地数据”操作，不把失败伪装成空状态或浏览器预览。

验收标准：读取失败不会触发真实行情、盯盘或盘后复盘；重试可恢复并只执行一次；慢速响应不覆盖早期编辑；CAS 冲突保持可恢复提示；前端/Host 测试、构建、安全审计、架构审查和窄屏回归通过。

### 11.79 Stage 3BD 搜索标的详情与真实行情闭环（本轮增量）

修复全局命令面板搜索到的非自选标的无法获取行情的问题，让“搜索 → 查看详情 → 决定是否收藏”成为可用的研究入口。

### 11.77 Stage 3BB Local Host 用户状态单一事实源（本轮增量）

确保本地 Web 调试与桌面端观察同一份用户状态，避免 Host 暂时离线时回退到浏览器存储造成数据分叉或恢复后覆盖。

1. localhost 页面读取用户状态必须严格经过 Local Host `/api/user-state`；Host 网络错误、超时或无效响应向 Store 传播并显示可恢复错误，不读取浏览器 `localStorage` 作为替代。
2. 非 localhost 的浏览器预览继续使用受限的浏览器本地状态；桌面端继续使用原生 Host。三种环境的凭据、模型、行情缓存和用户状态边界不混用。
3. Host 恢复后重试读取 canonical revision 和用户状态；离线期间不自动写入另一份状态，也不把陈旧数据回写 Host。

验收标准：Local Host 离线时不会读取或覆盖浏览器状态；健康 Host 可读回 canonical revision；浏览器预览与桌面行为不回归；前端/Host 测试、构建、安全审计、架构审查和窄屏回归通过。

### 11.80 Stage 3BE 共享 CAP 请求的独立取消（本轮增量）

修复多个页面或后台任务同时读取同一 CAP 数据时的取消耦合：首个调用方切换渠道或离开页面，不应连带中止仍在等待相同真实结果的其它调用方。

1. 同一数据类型、参数、Provider 和渠道的在途 CAP 请求继续合并为一次上游调用；每个调用方拥有独立的等待与取消信号。
2. 任一等待者主动取消只结束自己的等待，不将取消错误广播给其它等待者；仍有等待者时上游请求继续执行并可写入短时真实数据缓存。
3. 所有等待者都取消后才中止上游请求；取消不进入重试，不生成“超时”或成功审计，也不污染新渠道、新参数或用户状态。
4. 共享请求成功、失败、主动取消和缓存命中继续使用统一日志脱敏与费用口径；页面和桌面不新增第二套数据契约。

验收标准：并发 CAP 请求只产生一次上游调用；首个调用方取消时其它等待者仍能收到真实结果；全部等待者取消时上游可被中止；主动取消不重试、不误报超时；前端/Host 测试、构建、安全审计、架构审查和窄屏回归通过。

### 11.81 Stage 3BF 共享 CAP 结果提交与配置切换回收（本轮增量）

补齐共享请求在取消和配置切换边界下的缓存与资源生命周期，避免真实数据已经返回却没有复用，或旧配置继续消耗上游费用。

1. 共享 CAP 请求的短缓存由上游请求本身提交，而不是由首个等待者提交；首个等待者离开后，仍在等待的调用方收到成功结果时，后续调用可以命中同一真实结果。
2. 凭据、数据渠道、Provider 或网关设置变化时，立即使缓存代次失效并中止尚未完成的上游 CAP 请求；旧请求不得写入新代次缓存。
3. 配置切换导致的主动取消不进入成功审计、不触发重试，也不伪装成 Host 超时或普通上游失败；正常上游失败仍保留可排查的脱敏日志。
4. 该阶段不改变 CAP 参数、用户状态和费用口径；缓存只存在进程内短 TTL，清理工具缓存文件的行为保持幂等。

验收标准：首个等待者取消时其它等待者仍可使真实结果进入短缓存；配置变化会中止并移除旧在途请求；取消原因可识别且不产生错误 CAP 审计；缓存代次不能被旧请求回写；单元测试、构建、安全审计、架构审查和窄屏回归通过。

### 11.82 Stage 3BG Host 行情正数边界前移（本轮增量）

将行情可信性门禁前移到 Local Host 的 CAP 响应归一化层，避免无效价格进入共享缓存、审计和派生指标。

1. `quote` CAP 返回的价格必须是可解析的有限正数；`0`、负数、空字符串、`NaN` 和缺失值统一视为不可用行情并拒绝归一化。
2. 无效行情不得写入进程内短缓存、用户状态、组合计算、市场宽度或异动信号；其它合法字段不作为价格替代品。
3. 前端现有正数门禁继续保留，用于防御桌面原生或历史缓存响应；本阶段不改变 CAP 参数、费用口径、来源字段和缺失数据文案。

验收标准：Host 对正数、零、负数、空字符串和缺失价格有单元测试；无效响应不会进入缓存或真实行情状态；前端/Host 测试、构建、安全审计、架构审查和窄屏回归通过。

### 11.83 Stage 3BH CAP 缓存命中语义与回退门禁（本轮增量）

统一固定 CAP 直连、进程内缓存和固化工具回退的可观测语义，避免把真实上游调用误标为缓存命中并触发不必要的模型 Search。

1. 固定 CAP 首次上游调用返回 `cacheHit=false`；仅进程内短缓存或共享在途结果复用返回 `cacheHit=true`，`dataCacheHit` 与该语义保持一致。
2. `details` 同时请求公司资料和估值指标时，只有所有子请求均复用缓存才算缓存命中；部分命中必须标记为未完全命中。
3. Pi 对话审计区分 `cap-call` 与 `cached-call`；真实固定 CAP 结果不再伪装为固化工具缓存，缓存/回退逻辑不得因错误标记重复触发 Search。
4. 不改变 CAP 参数、费用统计、真实数据边界和固化工具失效策略；开发面板继续显示脱敏请求、成本和命中状态。

验收标准：首次直连、短缓存命中、在途合并、详情部分命中和固化工具回退均有测试；错误命中不会触发额外模型调用；前端/Host 测试、构建、安全审计、架构审查和窄屏回归通过。

### 11.84 Stage 3BI CAP 回退错误分类与成本护栏（本轮增量）

避免固定 CAP 失败时无差别触发 Search/固化工具回退，减少认证失败、限流和上游故障下的重复延迟与费用。

1. 直接 CAP 返回 401/403 时立即传播权限错误，不再发起固化工具调用；用户可按统一错误态去设置或检查凭据。
2. 408/425/429/5xx、超时和网络抖动经过既有有界重试后直接返回可恢复失败，不因一次暂时故障追加 Search；不会把一次失败计为成功或缓存命中。
3. 固定能力明确返回 404/410、工具不存在/失效等错误时允许回退已验证的固化工具；无 HTTP 状态的结构化结果校验失败仍可尝试固化工具，以兼容能力信封差异。
4. 交易日历继续 fail closed，不得回退到固化工具或按工作日猜测；回退决策和原因写入脱敏开发日志，CAP 与模型成本口径不变。

验收标准：401/403、限流、超时、5xx 不触发额外 Search；能力失效时仍可回退；交易日历失败不回退；回退分类和费用边界有单元/集成测试，前端/Host 测试、构建、安全审计和架构审查通过。

### 11.85 Stage 3BJ 对话 CAP 回退错误分类（本轮增量）

补齐 Stage 3BI 只覆盖 HTTP 数据路由、未覆盖模型 `foliomind_data` 工具调用的边界，避免对话链路在固定 CAP 已明确失败后继续追加 Search/固化工具调用。

1. 模型调用 `foliomind_data` 时，401/403、408/425/429/5xx、超时和网络错误沿用统一回退门禁，直接向当前对话返回可恢复失败，不再追加 Search、Inspect 或固化 Call。
2. 固定能力明确失效（404/410、工具不存在/过期）或无 HTTP 状态的响应结构校验失败时，才允许继续使用既有固化工具；交易日历无论入口均 fail closed。
3. 对话审计先记录固定 CAP 的失败类别；仅实际执行固化工具时才记录 `cached-call`，开发面板不得把认证/限流失败伪装为缓存未命中。
4. 该门禁不改变模型工具 schema、CAP 参数、成本提取或用户状态；同一次对话最多为一个 `foliomind_data` 请求执行一次固定 CAP，避免重复扣费。

验收标准：模型工具调用遇到 401/403、限流、超时和 5xx 时只产生一次模型请求和一次固定 CAP 请求，不触发 Search；能力失效时仍可回退；交易日历失败不回退；审计和友好错误状态可验证，Host 单元/真实 HTTP 集成测试、前端/Host 测试、构建、安全审计和架构审查通过。

### 11.86 Stage 3BK 跨市场交易日门禁（本轮增量）

修复自动盘后复盘将所有持仓默认按上交所判断交易日的问题，避免混合市场或海外持仓在错误的交易日生成复盘。

1. 沪市、深市、港股和中金所持仓按各自固定交易所代码查询真实交易日历；同一组合包含多个已支持交易所时并行/分组核对，只有所有市场均为交易日才进入行情刷新。
2. `沪深`/`A股` 等不明确市场仅在证券代码前缀能够无歧义映射时解析为沪市或深市；未知代码、未支持市场（例如美股）直接 fail closed，显示可恢复的手动复盘提示，不猜测交易日。
3. Web 本地调试与桌面原生 worker 使用同一市场解析语义；日历调用日志记录实际 marketcode、日期、结果和耗时，日历失败不回退固化工具、不按工作日推断。
4. 该阶段不改变用户状态 schema、报价 CAP 参数和复盘幂等键；日历状态仍以组合自然日为粒度，跨时区市场在支持专属时区和收盘时间前保持手动复盘。

验收标准：沪深混合组合分别调用 `212001` 与 `212100`；港股调用 `212200`；美股/未知代码不发起错误的 SSE 请求并保留友好状态；任一市场休市或日历失败都不生成复盘；前端/Rust 单测、构建、安全审计和架构审查通过。

### 11.87 Stage 3BL Local Host 客户端断开回收（本轮增量）

修复 Web 本地调试页面关闭、切换路由或主动取消后，standalone Host 仍继续执行上游 CAP/模型请求的问题，避免无法交付的请求继续占用连接和产生费用。

1. standalone Host 为每个 HTTP 请求创建生命周期信号；浏览器连接在上游调用期间断开时，Host 必须取消该请求所属的 CAP、模型或能力目录调用，并释放共享请求的等待者。
2. 客户端断开只影响当前请求，不中止其它仍等待同一共享 CAP 结果的调用方；仍有等待者时上游继续执行并可提交短缓存，所有等待者离开后才中止上游。
3. 客户端断开不写入用户状态、不产生成功审计、不触发回退或重试；开发日志记录受控的 499/`client-disconnected` 事件，响应连接关闭后不得再次写入响应体。
4. 正常完成、Host 超时、用户主动取消和客户端断开保持可区分；恢复新请求时运行时锁、缓存和并发额度均可正常复用。

验收标准：Local Host 集成测试让客户端在 CAP 请求进行中断开，并验证上游连接被取消、Host 运行状态释放和日志原因可识别；共享请求的其它等待者行为不回归；前端/Host 测试、构建、安全审计和架构审查通过。

### 11.88 Stage 3BM 持久化失败显式反馈与可恢复保存（本轮增量）

修复用户状态写入失败后界面仍显示成功、后台异步写入产生未处理拒绝的问题，保证本地调试和桌面端都能明确恢复。

1. 需要持久化的用户操作只有在 canonical Host 状态写入成功后才报告成功；保存失败沿用脱敏错误并传播给当前操作，页面保留内存编辑供重试。
2. 通知、调度和其它 fire-and-forget 写入必须显式捕获失败，不得产生浏览器未处理 Promise 拒绝；失败仍通过全局通知和对应页面状态可见。
3. 全局通知区分普通保存失败（“重试保存”）与 revision/CAS 冲突（“重新读取”），按钮在请求进行中去重，避免重复写入或覆盖另一窗口的修改。
4. 重试成功后显示明确的保存完成状态；冲突恢复必须重新读取 canonical 状态，不自动静默覆盖远端记录。该阶段不改变用户状态 schema、凭据边界或费用口径。

验收标准：保存失败会拒绝当前变更操作并出现可操作通知；重复点击只产生一次重试写入；CAS 冲突提供重新读取入口；后台调度和通知路径无未处理拒绝；前端/Host 测试、构建、安全审计、架构审查和窄屏回归通过。

### 11.89 Stage 3BN 自选汇总统计（本轮增量）

参考主流行情产品在 Watchlist 中提供最小值、最大值、平均值和中位数的做法，为市场页补充字段级自选汇总，帮助用户快速判断当前盘面分布。

1. 汇总只消费当前 `liveQuotes` 中价格有效且未明确过期的真实行情；缺失价格、无效价格和过期行情不参与统计，并分别显示有效覆盖数与过期提示。
2. 对最新价、涨跌幅、成交量、成交额、换手率、市盈率和市净率逐字段独立计算最小值、平均值、中位数和最大值；某个字段缺失不影响其它字段，字段无有效值时显示“暂无真实数据”。
3. 汇总展示跟随行情刷新和列视图变化更新，不新增上游请求，不把汇总结果写入用户状态、缓存或成本账本；Web 与桌面复用同一组件和真实数据边界。
4. 无凭据、请求失败或没有有效行情时保持空态，不使用示例数字；格式沿用行情页既有单位和涨跌方向格式。

验收标准：有效、缺失、无效价格、过期行情和偶数样本中位数均有单元测试；市场页能看到字段级汇总并随列设置收敛；无真实数据时为空态；前端/Host 测试、构建、安全审计、架构审查和 1440px/390px 窄屏回归通过。

### 11.90 Stage 3BO 盯盘 CAP 错误分类与回退护栏（本轮增量）

补齐固定 CAP 盯盘直连与模型 Search 回退之间的错误边界，避免认证失败、限流或上游故障被吞掉后再次发起慢且可能扣费的模型查询。

1. 盯盘固定 CAP 返回 401/403、408/425/429/5xx、超时、网络断开或 Local Host 主动取消时，直接生成可恢复的友好错误，不再调用模型 Search；原始错误仅进入脱敏审计，不在界面泄露凭据或上游详情。
2. 多条件盯盘只要任一直接 CAP 命中上述阻断类错误，就整体保持失败态，不使用其它条件的部分结果，也不追加固化工具或模型回退，避免误触发和错误告警。
3. 只有能力不存在/失效（404/410 或明确工具缺失）及无 HTTP 状态的结构不可用响应，才允许沿用一次受控模型 Search 回退；回退原因和实际调用分别记录，不能把失败标为成功或缓存命中。
4. 交易日历继续 fail closed；本阶段不改变规则 schema、触发去重、CAP 参数或费用提取口径，Web 与桌面复用同一分类语义。

验收标准：401/403、限流、超时、5xx 和 Host 取消均验证不调用 `askPi`；能力缺失仍可受控回退；多条件阻断不会消费部分结果；通知只展示友好错误，开发日志保留可排查的脱敏原因；前端/Host 测试、构建、安全审计、架构审查和窄屏回归通过。
### 11.91 Stage 3BP 成本提取可信边界（本轮增量）

修复费用账本把金融数据中的业务金额误识别为调用费用的问题，并统一 Local Host、桌面 CAP 与 Pi 审计的计费字段口径。

1. 费用提取只接受明确的 `qveris_cost`、`qverisCost`、`cost`、`charged_credits`、`credits_used` 或 `fee` 字段；结构化费用对象可读取 `amount`/`value`/`credits`，但任意业务数据中的 `amount`、价格、成交额和序列数字不得作为费用。
2. CAP 与模型费用继续按调用类型和单位隔离；缓存命中只记录复用事件，不计入上游调用次数、已知费用笔数或费用合计。
3. 未发现明确计费字段时显示“费用未返回”，不使用固定单价、余额变化或响应中的业务数值推断费用；原始响应、凭据和完整业务数据不进入调试日志。
4. Web Host、桌面 CAP 和后台调度复用同一字段白名单语义；兼容网关返回的嵌套 `usage`/`billing`/`meta` 费用对象，不改变现有对外数据 schema。

验收标准：业务 `amount`/价格/序列值不会进入费用账本；显式数值和结构化 `cost` 能正确保留金额与单位；缓存复用不膨胀调用分母；Local Host/前端/Rust 单测、架构审查、构建、安全审计和正式安装包流程通过。

### 11.92 Stage 3BQ 数据连接启动状态可信化（本轮增量）

修复应用启动时连接状态尚未读取却短暂显示“预览模式”的误导，避免用户把连接初始化阶段误认为浏览器演示或错误地依赖示例数据。

1. Store 启动时将数据连接标记为“读取中”，直到 Local Host/桌面返回真实配置或明确错误；连接未确认前不显示“预览模式”、不触发行情请求，也不把缺失行情解释为未配置。
2. 首页行情状态条、自选侧栏和价格摘要显示一致的“正在读取数据连接”文案；读取期间操作按钮禁用，价格、涨跌和图表保持空值，不使用示例数字。
3. 连接读取失败时显示脱敏、可恢复的设置入口；只有明确返回浏览器演示状态时才显示“预览模式”，真实 API Key 状态恢复后沿用既有自动刷新和数据渠道切换门禁。
4. 该阶段不改变凭据保存、CAP/模型调用、用户状态和费用口径；仅收紧启动时状态机的可见语义。

验收标准：连接读取中的首页不出现“预览模式”或示例行情；成功读取后自动进入真实/未配置状态；读取失败可进入设置重试；前端单测、构建、安全审计、架构审查和窄屏回归通过。

### 11.93 Stage 3BR 组合表现趋势（本轮增量）

参考 Koyfin/TradingView 等行情产品对组合历史表现的展示方式，为已有盘后复盘增加轻量趋势视图，让用户能从连续真实快照判断组合表现变化，而不需要逐条打开记录。

1. 趋势只消费已保存复盘中的真实 `totalPnlPercent` 和交易日；同一交易日保留最新快照，日期或盈亏比例缺失时跳过，不插值、不补造点位。
2. 少于两个有效快照时显示可解释空态；达到两个快照后展示起点、最近值、百分点变化和可访问 SVG 趋势图，图中标注零线和每个真实快照日期。
3. 趋势卡不新增上游请求，不改变复盘、组合或费用账本，不把派生点位写入用户状态；删除复盘后趋势立即从剩余快照重算。
4. 窄屏下趋势图在卡片内部自适应，文字和数值保持可读；无有效真实快照时不出现示例数字或“收益预测”表述。

验收标准：日期排序、重复日期去重、无效日期/缺失盈亏过滤、数量上限和窄屏布局均有测试；组合页能从两次真实复盘显示趋势，单次或无复盘保持空态；前端/Host 测试、构建、安全审计、架构审查和正式安装包流程通过。

### 11.94 Stage 3BS 行情正数门禁一致性（本轮增量）

补齐 Stage 3BG 在 Host 边界之后的前端防御：部分旧缓存、原生响应或测试注入仍可能带有 `0`、负数或空字符串价格，不能因为展示层只检查有限数字而被误认为真实行情。

1. 统一 `isValidQuotePrice` 语义：价格必须可解析为有限正数；`0`、负数、空字符串、`NaN` 和缺失值均视为无行情。
2. 侧栏、实时行情条、市场概览、研究筛选、详情页、证据抽屉和组合复盘交易日门禁共享该判断；无效价格显示空态，不参与行情覆盖、排序、统计、风险或复盘生成。
3. 自选按最新价排序时，无效价格与缺失值保持在末尾且不影响稳定顺序；其它真实字段仍可按原契约独立展示，不能用价格之外的业务金额替代价格。
4. 该阶段是展示与派生层的防御性收紧，不改变 CAP 参数、缓存键、费用账本、用户状态或浏览器预览数据边界。

验收标准：正数、零、负数、空字符串和非有限值均有单元测试；市场宽度、研究筛选、侧栏、证据和自动复盘不会消费无效价格；构建、安全审计、架构审查和窄屏回归通过。

### 11.95 Stage 3BT Local Host 地址安全边界（本轮增量）

补齐桌面 Host 已有的出站地址校验，避免本地 Web 调试保存配置后把长期 API Key 发往不安全的远程 HTTP 地址，或通过 URL 查询参数/凭据泄露。

1. Local Host 保存、同步模型和所有 CAP/模型请求共用地址校验：仅允许 `http`/`https`，远程地址必须使用 HTTPS；`localhost`、`127.0.0.0/8` 和 `::1` 回环地址可使用 HTTP 进行本地 mock 调试。
2. 地址不得包含用户名、密码、查询参数、片段或首尾空格；无效配置在写入磁盘或发起上游请求前被拒绝，不能沿用旧地址静默发送凭据。
3. 已存在的配置文件每次被 Host 使用前重新校验；损坏或被手动篡改的配置进入友好错误状态，不伪装为浏览器预览，也不发起网络请求。
4. 本阶段不改变 CAP 参数、模型 schema、用户状态和凭据存储；桌面 Rust Host 与 Local Web Host 保持相同的信任边界和错误语义。

验收标准：回环 HTTP、HTTPS 远程地址可用；远程 HTTP、非 HTTP(S)、URL 凭据、查询参数、片段和空白地址均被拒绝；拒绝后配置不落盘、API Key 不出站；Host 单测、真实 HTTP 集成测试、构建、安全审计和架构审查通过。

### 11.96 Stage 3BU 动态 CAP 目录授权边界（本轮增量）

收紧开发面板动态能力测试的授权边界，避免浏览器直接提交任意 `tool_id/search_id` 消耗本地配置的 API Key，也避免旧目录卡片在能力发生变化后继续调用。

1. 动态 CAP 测试只接受最近一次由当前 Local Host 完成的能力目录搜索返回的 `searchId`，并要求 `toolId` 出现在该目录的已规范化工具列表中；目录缺失、搜索 ID 过期或工具不在目录内时，在 Host 本地以可恢复的 403 错误拒绝，不发起上游请求。
2. 目录每次刷新都替换旧目录绑定；旧卡片需要重新加载目录后才能测试。固定 CAP 白名单、模型运行时的 Search → Inspect → Call 阶段约束不受影响。
3. 目录校验发生在参数校验和网络请求之前，拒绝事件记录脱敏的失败原因，不记录完整凭据或未经验证的业务参数；通过校验的参数仍按动态试验台的长度和对象边界发送。
4. Web 与桌面继续只将固定白名单能力接入产品链路；动态目录测试只是开发验证入口，不自动改变固化工具缓存、用户状态或 Skill 暴露列表。

验收标准：未发现工具、旧 `searchId` 和目录外 `toolId` 均返回 `CAPABILITY_NOT_VERIFIED` 且上游调用次数为零；当前目录中的工具可正常测试并保留真实返回；Host 单测、真实 HTTP 集成测试、构建、安全审计和架构审查通过。

### 11.97 Stage 3BV Skill 安装状态持久化（本轮增量）

修复 Skill 市场只在内存切换安装状态的问题，避免用户刷新 Web、重启桌面或在 Web/桌面之间迁移后已安装能力静默丢失。Skill 元数据仍由应用版本提供，用户状态只保存非敏感的 Skill ID，不把 Skill 内容、凭据或运行日志写入状态。

1. 安装/取消安装操作必须等待当前 Host 的用户状态保存成功；保存失败时回滚界面状态并显示可重试通知，不能让用户误以为已安装。
2. Web Local Host、桌面 Rust Host 和浏览器预览使用同一个 `installedSkillIds` 状态字段；旧版状态缺少该字段时安全迁移为内置的基本面透视与智能盯盘 Skill。
3. 状态归一化限制 Skill ID 字符集、去重和数量上限；未知 ID 不改变当前应用的 Skill 元数据，也不能通过路径片段进入状态文件。
4. 备份导入/导出保留已安装 Skill ID，但不包含 Skill 内容、API Key、模型配置、CAP 缓存或运行日志；并发保存按单个 Skill 的变更合并，避免不同窗口安装不同 Skill 时互相覆盖。

验收标准：安装或取消安装后刷新/重启仍保持；旧状态获得安全默认值；保存失败会回滚并可重试；Web/桌面 schema、备份和 CAS 合并一致；前端单测、Rust 单测、构建、安全审计和架构审查通过。

### 11.98 Stage 3BW 固定 CAP 页面回退错误护栏（本轮增量）

收紧行情、详情、序列和事件页面在固定 CAP 失败后的恢复边界，避免认证失败、限流、超时或上游故障被误转为 Agent Search → Inspect → Call，造成额外等待和费用。

1. 页面固定 CAP 请求只有收到明确的 `TOOL_CACHE_MISS`、`CAPABILITY_NOT_FOUND` 或 HTTP 404 能力缺失信号时，才允许进入 Agent 发现路径；正常 CAP 结果、空结果和结构化失败不因缺少字段而重复搜索。
2. 401/403、408/425/429、5xx、超时、网络断开和主动取消沿用现有友好错误与重试入口，直接返回页面对应的真实数据状态，不追加模型调用，也不把失败当作缓存命中。
3. Host 和桌面端的回退分类继续作为第一道门禁；前端再做一次防御性校验，防止旧 Host、原生错误字符串或测试注入绕过错误分类。缺少结构化错误码时默认不回退，只有明确的能力缺失文案可恢复。
4. 回退决策不改变 CAP 参数、缓存、用户状态和费用账本；开发面板保留一次直接 CAP 失败的脱敏审计，只有实际进入 Agent 发现时才记录后续模型/工具调用。

验收标准：认证失败、限流、超时、5xx 和网络错误只产生一次固定 CAP 请求且不调用 Agent；明确能力缺失仍可发现并固化替代工具；空结果保持真实空态；Web/桌面错误文案可恢复；前端/Host 测试、构建、安全审计、架构审查和正式安装包流程通过。

### 11.99 Stage 3BX 动态 CAP 目录会话绑定（本轮增量）

补齐动态能力目录在 Local Host 重启后的授权边界。目录元数据可以保留用于开发面板检查，但上一 Host 进程完成的 Search 不能替新进程授权新的计费调用。

1. 每个 Local Host 进程生成独立的目录会话标识；能力目录写入缓存时保留该标识，重启后仍可展示上次的 query、tool、searchId 和更新时间，但这些元数据只用于诊断与重新发现提示。
2. 动态 CAP 测试除校验当前目录中的 `toolId/searchId` 外，还必须校验当前 Host 会话标识；目录缺失、会话不匹配或工具不在目录内时，在网络请求前返回 `CAPABILITY_NOT_VERIFIED`，不消耗上游额度。
3. 用户必须在新 Host 会话中重新刷新能力目录后才能测试动态工具；刷新成功后沿用现有参数对象边界、脱敏日志和费用记录。固定 CAP 产品链路、Skill 白名单和模型 Search → Inspect → Call 不受影响。
4. Web 与桌面继续只把固定契约用于产品行情和对话，动态目录仅作为开发验证工作台；会话标识不进入用户状态、备份或对外工具 schema。

验收标准：重启 Host 后旧目录仍可查看但使用旧 `searchId/toolId` 的测试在出站前返回 403 且上游调用次数为零；新目录搜索后同一工具可正常测试；会话不匹配、目录外工具和旧搜索 ID 均有 Host 单测与 HTTP 集成测试，构建、安全审计、架构审查和正式安装包流程通过。

### 11.100 Stage 3BY 详情与图表请求主动取消（本轮增量）

收紧选中标的详情和图表序列的生命周期，避免用户快速切换标的或周期时，已经失去展示价值的上游请求继续占用网络、延迟和费用。

1. 详情请求只服务于当前选中标的；新的标的详情请求开始前主动取消旧请求，并保留代次保护，旧响应不得写入新标的状态。
2. 图表序列请求只服务于当前标的和周期；切换标的或周期时主动取消旧请求，取消须向 Local Host/桌面传递 `AbortSignal`，不得把主动取消显示为普通数据故障。
3. 取消只影响被替换的详情/序列请求，不中止仍有展示价值的实时行情、其它标的独立刷新或共享 CAP 等待者；配置切换仍沿用全局回收门禁。
4. 该阶段不改变真实数据、缓存键、费用字段或用户状态 schema；主动取消的请求不应产生后续 Agent 回退或重复重试。

验收标准：详情和序列切换测试能观察到旧 signal 已取消，旧结果不污染新标的/周期；取消后新请求可正常完成；实时行情并发和共享 CAP 取消语义不回归；前端/Host 测试、构建、安全审计、架构审查和正式安装包流程通过。

### 11.101 Stage 3BZ Skill 备份导出闭环（本轮增量）

修复设置页导出备份未携带已安装 Skill ID 的状态断点，确保 Skill 安装偏好在 UI 导出、跨设备导入和 Host/桌面持久化之间保持一致，同时继续隔离凭据与运行时数据。

1. 设置页导出 JSON 必须从当前 Skill 元数据派生 `installedSkillIds`，只写入已安装 Skill 的稳定 ID，不复制 Skill 内容、权限、凭据或运行日志。
2. 导出的备份必须沿用统一用户状态 schema 的归一化和数量/字符集限制；导入后保留已安装的有效 ID，未知、重复和路径片段 ID 继续被过滤，旧版备份保持兼容。
3. 导出操作不得把 API Key、模型网关、模型目录、CAP 缓存、调用审计或当前运行态写入 JSON；Web、Local Host 和桌面端使用同一字段语义。

验收标准：在设置页安装 Skill 后导出 JSON，再通过现有解析/导入链路恢复时仍保留对应 ID；备份正文不含凭据或运行时配置；前端归一化/导出回归、架构审查、安全审计、构建和正式安装包流程通过。

### 11.102 Stage 3CA 详情与图表取消状态回收（本轮增量）

补齐主动取消后的本地状态生命周期，避免旧请求虽已停止网络等待，但遗留的 loading 标记阻塞用户再次查看标的或周期。

1. 详情请求被新标的替换时，旧标的的 loading 状态必须立即释放，不能把旧请求标记为已加载或错误；用户返回该标的时可以重新发起请求。
2. 图表周期或标的切换时，旧请求必须立即释放对应的 `symbol/range` loading 状态，新周期可以立刻取得自己的请求槽位；旧响应和旧错误不得污染当前周期。
3. 取消后的清理必须按请求上下文绑定，不能在快速切换后把新请求的 loading 状态误清除；全局配置切换和用户状态替换仍沿用统一资源回收门禁。
4. 该阶段不改变真实数据、缓存键、费用账本或用户状态 schema；主动取消不显示为普通数据失败，也不追加 Agent 回退。

验收标准：详情快速切换后旧标的可再次加载；图表快速换周期后旧周期 loading 释放且新周期立即调用；连续三次切换不会清除当前请求状态；前端/Host 测试、架构审查、构建、安全审计和正式安装包流程通过。

### 11.103 Stage 3CB 分层行情轮询（本轮增量）

将行情刷新从固定全量轮询升级为接近主流行情产品的重点标的低延迟、普通自选低频同步，兼顾实时性、上游限流和调用成本。

1. 当前选中标的、持仓标的和启用的单标的盯盘规则进入重点池，重点池每 15 秒刷新；其余自选进入全量池，每 180 秒刷新。手动“刷新行情”和设置变更仍可立即刷新完整自选。
2. 重点刷新只提交当前重点池中仍存在于自选的标的，不改变非重点标的已有真实行情；全量刷新继续覆盖所有自选并复用既有并发、缓存、取消和费用审计语义。
3. 页面不可见、窗口失焦或连接未确认时不发起后台轮询；页面重新可见/获得焦点时只优先刷新重点池，避免恢复瞬间重复扫全量。
4. 不支持的 symbol、空重点池和正在进行的全量请求不产生额外请求；主动刷新、数据渠道切换、错误恢复和桌面后台调度的真实数据边界不变。

验收标准：重点刷新只调用重点池，普通自选不会被带上；全量刷新仍覆盖全部自选；15 秒/180 秒常量、可见性暂停、焦点恢复和渠道变更行为有测试；前端/Host 测试、架构审查、构建、安全审计和正式安装包流程通过。

### 11.104 Stage 3CC 脱敏开发日志持久化与导出（本轮增量）

让本地调试和桌面排障在 Host 重启后仍保留足够证据，同时避免把凭据、原始提示词或完整敏感响应写入磁盘。

1. Local Host 将已脱敏的接口、参数摘要、返回摘要、状态、耗时、费用和失败原因追加到用户配置目录的 NDJSON 日志；日志文件权限限制为当前用户，单条内容继续沿用现有长度和密钥脱敏边界。
2. 日志至少保留最近 180 天，并限制为有界文件和最近 2,000 条记录；加载或定期压缩时清理过期/损坏行，不阻塞行情和对话请求，磁盘写入失败不得影响业务响应。
3. 开发面板打开时从 Local Host 恢复最近日志；提供 JSON 导出和一键清空。导出只包含当前已脱敏日志，清空必须同时删除内存和磁盘副本，并在完成后刷新为空态。
4. 桌面端继续展示当前运行时事件并支持导出；日志不进入用户状态备份、CAP 缓存或对外 Skill schema。普通用户页面不展示开发日志入口。

验收标准：Local Host 重启后开发面板可恢复此前日志；凭据和 Bearer token 不出现在日志/导出文件；日志超过保留期或上限会有界压缩；写盘故障不阻塞业务；导出和清空操作有可访问反馈；Host 集成测试、前端测试、架构审查、安全审计、构建和正式安装包流程通过。

### 11.105 Stage 3CD 首次运行零副作用与配置清单（本轮增量）

降低首次配置的意外费用和认知负担，让用户明确知道哪些能力已连接、哪些动作仍需主动触发。

1. 新安装的 Web、Local Host 和桌面端不再预置启用的盯盘规则；用户保存 API Key 或恢复数据连接时不得隐式触发任何盯盘 CAP 或模型调用。旧版本只在状态仍是完全未改动的 `r1/r2` 默认规则、无通知和无历史时迁移清空；用户编辑、禁用、触发、增加规则或产生通知/历史后全部保留。
2. 个股工作区在用户状态和连接状态读取完成后显示“开始使用”清单：连接真实数据、获取首个行情、开启 Agent 对话（后者可选）。清单只提供设置或一次主动行情操作入口，未返回的价格、指标和公司资料保持空态，不用演示值补齐。
3. 清单在真实数据、首个行情和已选模型均就绪后自动隐藏；加载中或连接错误时不制造重复提示。Web 与桌面复用同一真实数据判断、用户状态 schema 和错误恢复语义，窄屏与键盘操作保持可用。

验收标准：全新状态的盯盘规则为空且保存凭据不产生后台 CAP；旧未改动种子可安全迁移而用户状态不被误删；清单在连接前、行情为空和模型未配置时给出下一步并可恢复；真实行情为空时页面继续显示空态；前端、Host、Rust 单测，架构审查、安全审计、构建和正式安装包流程通过。

### 11.106 Stage 3CE 可重复的真实数据 Playwright 验收（本轮增量）

让无凭据本地调试和持续集成能够稳定验证真实空态、错误恢复和跨页面流程，避免测试环境的持久状态制造假失败。

1. Playwright 流程必须可重复执行：Skill 已安装、未安装或 Host 重启后的状态都视为合法起点；测试只在必要时安装 Skill，不重置用户数据，也不把测试操作写入产品状态契约之外。
2. 无 API Key 的测试会主动经过行情、筛选、组合、盯盘、设置和对话路径；Local Host 返回的预期 502/真实数据不可用只记录为“预期上游错误”，不能掩盖 JavaScript、页面崩溃或意外控制台错误。
3. 报告同时保存成功步骤、视口尺寸、预期上游错误、控制台错误和页面错误；桌面/移动视口横向溢出、交互控件不可达和空态文案回归都必须阻断验收。

验收标准：Playwright 连续运行两次均通过且无需清理 Skill 状态；无凭据时不显示伪造行情，预期上游错误与前端错误可区分；桌面和移动视口无横向溢出；报告可定位失败步骤；脚本、前端测试、架构审查、安全审计、构建和正式安装包流程通过。

### 11.107 Stage 3CF 盯盘规则管理闭环（本轮增量）

参考 TradingView 的 watchlist alert 管理和 Koyfin 的 alerts hub，将盯盘页从“创建后只能启停/删除”补齐为可持续维护的规则工作台；本阶段不改变真实数据、触发判定或通知 schema。

1. 规则列表支持按条件、标的代码和策略名称搜索；支持“全部 / 运行中 / 已停用”状态筛选，并支持按最近活动、条件名称和运行状态排序。过滤只改变客户端展示，不触发额外数据请求。
2. 每条规则提供“编辑”入口，编辑表单复用新建规则的范围、条件组合、逻辑和检查频率字段；保存成功后保持规则 ID、已存在的 `monitorHistory` 审计记录和用户状态兼容性。
3. 修改条件、标的、范围或频率后清除旧的 `lastCheckedAt`、`lastTriggeredAt`、`lastSignalTriggered` 和 `lastSignalBySymbol` 边沿状态；下一次真实检查完成前不得沿用旧状态触发通知，避免改规则后误告警。
4. 编辑持久化失败时恢复原规则并显示可恢复错误；成功编辑不清除历史、不新增模型调用、不修改 API Key、CAP 缓存或费用账本。Web 与桌面共用同一 Store/Host 契约。
5. 搜索无结果、无规则和数据未配置继续使用各自的真实空态；控制件具备标签和键盘焦点，窄屏下工具栏可换行且不产生水平溢出。

验收标准：可以搜索、筛选、排序和编辑已有规则；编辑后规则字段与触发边沿正确重置，历史检查记录仍可展开；保存失败不会丢失原规则；列表操作不发起上游请求；前端/Store 单测、架构审查、构建、安全审计和桌面/移动 Playwright 回归通过。

### 11.108 Stage 3CG Web/桌面盯盘状态契约对齐（本轮增量）

修复 Rust Host 用户状态结构落后于 Web 盯盘规则的问题，避免桌面读取并保存状态时丢失自选组规则的范围和逐标的触发边沿。

1. Rust `MonitorRule` 与共享用户状态契约一致保存 `scope`（`symbol`/`watchlist`）和 `lastSignalBySymbol`；旧状态缺失字段时分别安全默认到单标的范围和空 map。
2. `watchlist` 规则必须使用 `symbol: "*"`，单标的规则不得使用通配符；逐标的状态 map 有界、键经过文本校验，非法范围在桌面写入前拒绝。
3. 旧版 `r1/r2` 种子迁移只有在单标的范围、空触发状态且其它字段完全未改动时才允许清空；用户改成自选组、改条件或产生触发记录后必须保留。
4. Web、Local Host 和桌面 Rust 的序列化/反序列化往返不得改变规则范围、条件逻辑、触发边沿或历史；本阶段不新增上游请求、不改变费用和凭据边界。

验收标准：自选组规则经 Rust 读取并保存后仍为 `scope=watchlist`、`symbol=*` 且保留 `lastSignalBySymbol`；旧状态能获得安全默认值；非法 scope/通配符被拒绝；种子迁移不误删用户改动；Rust/前端测试、架构审查、构建、安全审计和正式安装包流程通过。
### 11.109 Stage 3CH Web/桌面跨进程用户状态锁（本轮增量）

补齐 Web Local Host 与桌面 Host 共享用户状态文件时的进程间互斥，避免两个 Host 都通过各自的内存锁后同时读取同一 revision 并覆盖写入。

1. Web Host 与 Rust Host 对 `user-state.json` 使用同名的独占锁文件 `.user-state.json.lock`；只有拿到锁后才能执行 revision/CAS 校验、短事务 mutation 和原子替换，读取仍使用原子文件快照。
2. 锁文件写入随机 owner token；正常释放前先核对 token，不能删除后来进程已经取得的新锁。锁等待有界（5 秒），超时返回 `USER_STATE_BUSY` 和可恢复提示，不把忙碌误报成保存成功或 CAS 冲突。
3. 进程崩溃遗留的锁超过 30 秒才允许下一进程回收；回收与新 owner 抢占存在竞争时必须重新尝试，正常短事务不应触发过期回收。锁目录沿用用户配置目录，不能进入备份、日志或对外工具 schema。
4. 该锁不跨越网络请求、模型调用或其它慢操作；Web Host 的进程内队列和 Rust 的线程内 Mutex 继续保留，三层边界共同保护同一状态文件。失败、超时和清理异常不能损坏已有状态。

验收标准：Web Host 与桌面 Host 并行保存同一状态时最多一个事务进入文件替换，另一个得到 `USER_STATE_BUSY` 或随后按 revision 合并；锁释放不会删除新 owner 的锁；崩溃遗留锁可在 30 秒后恢复；锁等待、回收和 token 竞争有 Node 单测，Rust 格式/Clippy/单测、架构审查、安全审计、构建和正式安装包流程通过。

### 11.110 Stage 3CI 盯盘规则生命周期控制（本轮增量）

参考 TradingView 的告警触发频率与到期配置，将盯盘规则从“启用后长期边沿检查”扩展为可控的生命周期，降低误报、重复通知和不必要的数据调用成本。

1. 规则提供两种触发方式：默认“边沿触发”在条件从未满足变为满足时提醒，恢复后允许再次提醒；“单次触发”在第一次真实条件触发后自动停用，不再发起后续检查。缺失字段、未知结果和检查失败均不得消耗单次触发额度。
2. 规则可设置可选的有效期日期。日期按该日结束生效；到期后规则自动停用，调度器和手动检查均不得发起 CAP 或模型请求。留空表示长期有效；编辑并延长有效期后可重新启用，并清除旧触发边沿等待一次新检查。
3. 生命周期字段纳入 Web、Local Host、桌面 Rust 的用户状态 schema，旧状态安全默认为 `triggerMode=edge`、`expiresAt=null`；日期格式、触发方式和其它规则字段在 Host 写入前校验，非法值不得落盘。
4. 盯盘列表显示触发方式、有效期和“已过期”状态；已过期规则不能手动运行。保存、备份和跨端同步保留生命周期字段，不新增上游请求，也不把密钥或原始响应写入用户状态。

验收标准：边沿规则保持现有去重语义；单次规则首次真实触发后自动停用且第二次调用不发起请求；过期规则在手动与后台调度路径均不发起请求并持久化停用；旧状态获得安全默认值，非法 Rust/前端字段被拒绝；生命周期 UI 在窄屏和键盘操作下可用；前端/Store、Rust 状态、架构审查、构建、安全审计和正式安装包流程通过。

### 11.111 Stage 3CJ Release Web/Host 回归硬门禁（本轮增量）

将真实 Web 调试入口纳入正式发布前门禁，避免前端、Local Host、空态和跨页面交互回归后仍能生成可下载安装包。本阶段不连接真实 QVeris、不使用用户凭据，也不改变产品数据契约。

1. Release workflow 在桌面安装包构建前启动隔离的 standalone Web Host，运行无凭据 Playwright 流程，覆盖行情、研究、组合、盯盘、Skill、设置、对话、自选切换、重载和 390px 窄屏路径。
2. QA 必须验证真实数据未配置时保持空态/可恢复错误，不把预期的上游 502 当作 JavaScript 崩溃；控制台错误、页面错误、横向溢出和关键控件不可达均阻断发布。
3. 每次运行使用临时数据目录和 CI 安装的 Chromium，结束时回收 Web Host、日志和临时进程；报告、截图和 Host 输出作为 Actions artifact 保存，便于定位失败步骤。
4. `web-qa` 成功后才允许 Windows/macOS 桌面构建和 Release 发布；QA 失败不得生成或上传正式安装包。该门禁只覆盖无凭据边界，真实凭据、签名和升级烟测继续由发布环境专项验证。

验收标准：Release workflow 的 Web QA job 在桌面构建前执行；同一提交连续两次本地 QA 通过；CI 使用隔离 Host/数据目录并上传报告；预期上游错误与前端/page error 分开；QA 失败会阻断安装包构建；workflow 静态审查、Playwright、构建、安全审计和正式安装包流程通过。

### 11.112 Stage 3CK 本地敏感文件权限（本轮增量）

补齐本地配置落盘的隐私边界。用户状态包含持仓、交易计划和提醒，集成配置与工具缓存包含服务地址、模型目录和调用路由；这些文件不能依赖机器默认 `umask` 才获得保护。

1. Local Host 的用户状态、集成设置、固化工具缓存及其原子替换临时文件，在 POSIX 系统统一设置为 `0600`；每次替换后重新设置，既有宽权限文件也会在下一次写入时收紧。Windows 继续使用每用户配置目录，并不把凭据写入这些 JSON 文件。
2. 桌面 Rust Host 的用户状态、集成设置和 Pi 配置通过同一原子写入边界保护临时文件，再重命名为目标文件；POSIX 目标文件权限为 `0600`，不会因旧文件权限或进程 `umask` 放宽。
3. 权限收紧不得破坏原子性、备份恢复、跨进程 CAS 锁或日志写入；权限设置失败必须作为写入失败传播，不能报告用户状态已保存。权限字段不进入备份、开发日志或对外 Skill schema。
4. 本阶段不改变 API Key 凭据库、CAP/模型协议、用户状态字段和费用口径；仅收紧本地文件访问权限，并为 Windows/非 POSIX 行为保留可解释兼容路径。

验收标准：在宽 `umask` 下创建或替换 Local Host JSON，POSIX 权限仍为 `0600`；Rust 原子配置和用户状态写入具备同样测试；原有状态锁、备份恢复、Host 集成、前端、架构审查、安全审计、构建和正式安装包流程通过。

### 11.113 Stage 3CL 用户状态损坏恢复与最后有效快照（本轮增量）

解决状态文件被截断、写入中断或手工破坏时的静默回退问题，避免把用户的自选、持仓和盯盘配置误显示为默认数据并在下一次保存时覆盖。

1. Local Host 与桌面 Rust Host 在读取用户状态时必须校验文件大小、JSON 结构、共享 schema 约束和至少一个自选标的；主文件损坏时不得静默返回默认状态。
2. 每次 revision/CAS 保存新状态前，先将上一份已通过校验的状态原子写入同目录 `user-state.json.backup`；备份与主文件使用相同的私有文件权限和原子写入边界。
3. 主文件损坏或缺失且备份有效时，Host 自动恢复主文件并返回备份状态；主文件和备份都不可用时返回可操作的“导入备份文件”错误，不发起行情、模型或后台盯盘请求。
4. 恢复过程必须在现有跨进程文件锁和线程/进程内 I/O 锁内完成，保留 revision/CAS、脱敏 schema、日志不落盘和 Web/桌面一致性；恢复失败不得报告保存成功。

验收标准：Local Host 集成测试覆盖损坏主文件从最后有效快照恢复、双文件损坏的可恢复错误和恢复后 revision 保留；Rust 单测覆盖原子备份写入与 POSIX 权限；跨进程锁、前端状态加载、构建、安全审计、架构审查和正式安装包流程通过。

### 11.114 Stage 3CM 用户可见状态变更的持久化事务（本轮增量）

补齐少数乐观更新操作的保存失败边界，避免规则开关、规则删除、消息已读、自选删除和事件提醒在 canonical Host 写入失败后仍停留在界面或触达层，造成“看起来成功、重启后消失”的数据损失。

1. 规则启停、规则删除、复盘删除和自选删除先更新内存，随后必须等待 `persistUserState()` 成功；失败时只在目标记录仍未被后续编辑替换的情况下回滚该记录，并向调用方传播脱敏错误。
2. 单条消息已读、全部已读和主动新增消息遵循同一事务边界；失败时保留并发产生的其它消息，只恢复本次操作涉及的消息字段。
3. 事件提醒先写入 canonical 用户状态，保存成功后才发送系统通知；保存失败时移除本次提醒，不得发送无法在站内恢复的通知，也不得产生未处理 Promise 拒绝。
4. 所有 UI 入口必须消费 Promise 并展示可恢复错误；全局通知仍提供“重试保存”，不能以空 `catch` 隐藏失败。

验收标准：上述状态变更的持久化失败均能在单元测试中验证内存回滚/并发保留、错误传播和事件通知不发送；正常路径不改变现有 CAS、备份、审计和去重语义；前端测试、Host 测试、构建、安全审计和发布前 Web QA 通过。

### 11.115 Stage 3CN 模型网关连接诊断（本轮增量）

补齐“模型目录已同步但对话仍失败”时的最短诊断路径，避免用户只能进入对话页等待超时，无法判断 API Key、网关、模型选择还是 Runtime 的问题。本阶段参考主流金融工作台将数据连接和分析连接分开验证；探针由 Host 直接访问模型网关，不启动 Pi、不进入金融工具链。

1. 设置页在模型已同步并保存应用后提供“测试模型”入口；Host 只发送一次最小模型请求，省略工具定义并强制 `tool_choice=none`，要求返回可识别文本，不能通过静态成功文案或数据 CAP 结果判定模型可用。
2. 测试按钮在未配置凭据、网关地址/模型尚未保存、已有分析运行或运行时取消尚未完成时禁用或给出明确提示；测试中的按钮显示忙碌状态，不能并发启动第二次 Runtime 请求。
3. 成功结果显示模型 ID 和耗时；失败结果按凭据、超时、限流、运行时/网络、空响应分类为可恢复中文文案，不把上游 URL、token、原始异常堆栈写入普通设置页面。
4. 测试请求沿用现有 Host 鉴权、超时、脱敏审计和费用记录；用户明确点击才发起调用，并在界面提示可能产生模型费用。测试不得启动 Pi、写入对话历史、用户状态、CAP 缓存或 Skill schema。

验收标准：配置有效模型后可从设置完成一次最小模型请求并看到成功耗时；网关超时、凭据错误和空响应均有对应可恢复文案；测试期间不产生金融工具调用、不污染对话历史且不会与运行中的分析并发；前端/Runtime 单测、架构审查、构建、安全审计和正式安装包流程通过。

### 11.116 Stage 3CO 自选行情新鲜度（本轮增量）

修复高频自选侧栏只显示价格和涨跌幅、却无法判断每个标的数据时间的问题。主行情卡和证据抽屉已有来源/截至时间，但用户在快速浏览自选列表时仍可能把过期报价误认为实时数据。

1. 每个有效真实报价在自选侧栏增加紧凑的新鲜度标签，至少区分“新鲜”“可能延迟”和“时间未知”；标签使用统一 `quoteFreshness` 规则，不根据请求完成时间猜测上游数据时间。
2. 标签悬浮提示提供数据来源和完整数据时间；缺失价格、预览静态目录或未配置状态不显示新鲜度标签，继续显示原有空值/配置状态文案。
3. 新鲜度展示只改变侧栏信息层级，不改变 `liveQuotes`、CAP 请求参数、缓存键、排序结果、费用统计或真实数据边界；Web 与桌面共享同一组件和格式化函数。

验收标准：有效真实报价在桌面宽屏自选侧栏可看到新鲜度和来源/时间提示；超过 15 分钟的报价明确显示可能延迟，缺失时间显示时间未知；未配置或无效报价不出现伪造时间；窄屏无页面级横向溢出；格式化、组件、架构审查、构建、安全审计和发布前 Web QA 通过。

### 11.117 Stage 3CP 多市场行情时区标签（本轮增量）

修复跨市场行情时间按浏览器本地时区显示造成的理解偏差。用户可能同时观察 A 股、港股和美股，只有明确标注交易所时区，数据截至时间和新鲜度才可核验。

1. 行情时间格式化根据自选标的市场使用交易所时区：A 股显示北京时间，港股显示香港时间，美股显示美东时间，并通过 `Intl` 处理夏令时；已支持的伦敦、东京和中欧市场使用对应时区。

3. 时区只影响展示，不改变 `asOf` 原始值、新鲜度 15 分钟门禁、排序、缓存、CAP 参数、费用和用户状态；缺失或非法时间继续显示“数据时间未知”。

验收标准：同一 UTC 时间在 A 股、港股、美股行分别显示对应交易所时区；美股夏令时切换前后标签和时间正确；未知市场不显示错误的已知时区；主行情、自选、实时行情条、市场概览和表格保持一致，窄屏无横向溢出；格式化、组件、架构审查、构建、安全审计和发布前 Web QA 通过。

### 11.118 Stage 3CQ 未知市场时间与证据入口一致性（本轮增量）

补齐多市场时区改造后的安全边界：未知市场不能在界面中悄悄落入浏览器本地时区，所有展示行情截至时间的入口都必须携带标的市场上下文，避免同一报价在证据、研究和异动页面出现不同解释。

1. 市场代码匹配必须使用交易所代码的 token 边界，不能因为 `SSE` 出现在 `RUSSELL`、`US` 出现在自定义名称等子串而误判交易所；已知市场继续按交易所时区显示并处理夏令时。
2. 显式市场但无法识别时，完整时间和紧凑时间均使用带日期的 UTC 参考，并明确附加“时区未知”；不得使用浏览器本地时区伪装为来源时间。缺少市场仍保留既有兼容行为，并继续标记数据时间语义。
3. 行情证据抽屉、研究筛选、异动雷达和设置页数据连接诊断必须将标的市场传入统一格式化函数；原始 `asOf`、新鲜度门禁、排序、缓存、CAP 参数和费用口径不变。
4. 该阶段只改变显示与错误防误判边界，不改变 provider schema；未知市场仍可正常展示价格和其它真实字段，不能因为时区未知而丢弃有效行情。

验收标准：短代码子串不会错误映射时区；未知市场在完整/紧凑时间中均能看到 UTC 与“时区未知”；证据、研究、异动和连接诊断显示与主行情一致；无凭据空态、窄屏、格式化单测、前端回归、架构审查、构建、安全审计和发布前 Web QA 通过。

### 11.119 Stage 3CR 大规模自选渲染与长名称可用性（本轮增量）

改善自选数量增长后的交互稳定性。用户可能通过 CSV 导入或连续添加大量标的，侧栏和行情列表不应因为每次行情轮询、状态提示或窗口切换而重复计算和重绘全部行；同时长公司名称不能破坏价格列或让用户无法确认完整名称。

1. 自选侧栏在进入渲染前只对当前 watchlist 做一次规范化，分组数量和排序使用该稳定结果；单行组件按标的、行情和展示状态记忆化，未变化的行不得因其它行报价更新而重复构建。
2. 侧栏名称必须在窄列中单行省略，保留完整 `title`/悬浮提示和代码，不得挤压价格、新鲜度和移除操作；实时行情条、市场表格和研究结果的名称列同样保持可收缩、省略和可访问查看。
3. 长列表的非可见行使用浏览器原生 `content-visibility` 延迟绘制并提供固有尺寸，不能改变键盘顺序、点击详情、分组筛选、排序或真实数据空态；不引入会截断用户自选的数量上限。
4. 该阶段只优化前端派生与绘制，不改变 liveQuotes、CAP 请求并发、缓存、费用、用户状态和导入上限；浏览器不支持延迟绘制时仍以完整列表正确降级。

验收标准：长名称在侧栏可见省略且可通过 title 获取全文；分组筛选、排序、移除、详情打开和真实/预览空态不变；至少覆盖 200 个自选的渲染回归、窄屏无横向溢出、组件单测、架构审查、构建、安全审计和发布前 Web QA。

### 11.120 Stage 3CS 跨行情入口名称可访问性与大列表回归（本轮增量）

将 Stage 3CR 的可用性边界落实到所有行情入口，避免用户在实时行情条、市场表格或研究筛选中遇到长名称时无法确认标的；同时把 200 个自选的“不截断、不丢行”作为持续回归门禁。

1. 实时行情条、市场概览、市场自选表格和研究筛选的名称节点都必须保留完整 `title`，并与既有收缩/省略样式配合；键盘和鼠标打开详情的行为不变。
2. 实时行情卡抽取为记忆化行组件，单个报价更新时不重复计算未变化标的；其它页面继续通过原生 `content-visibility` 延迟非可见绘制并保持 DOM 顺序。
3. 前端回归至少创建 200 个合法自选，验证侧栏渲染行数、分组总数和空行情边界；不得用数量上限规避渲染压力，也不得写入示例报价。
4. 本阶段不改变数据请求、缓存、费用、导入上限或用户状态契约；只补齐跨入口可访问提示和可重复的性能回归证据。

验收标准：四类行情入口均可通过 title 获取完整名称；200 个自选全部存在且分组计数正确；实时行情条、市场表格和研究结果无页面级横向溢出，组件/架构审查/构建/安全审计和发布前 Web QA 通过。

### 11.121 Stage 3CT 大规模自选真实刷新完整性（本轮增量）

把 Stage 3CS 的渲染回归延伸到真实数据刷新调度，避免自选数量增长后因并发、异常或响应顺序导致部分标的被静默跳过。该阶段只验证现有 CAP 请求编排，不引入额外请求或费用。

1. 全量刷新面对 200 个及以上合法自选时，必须为每个标的建立且完成一次独立的真实行情请求；请求结果顺序可以不同，但不能因为并发 worker、状态更新或其它标的失败而截断后续标的。
2. 每个标的的请求仍遵守既有并发上限、取消代次、固化 CAP 缓存和费用审计；同一轮不得重复请求同一规范化 symbol，也不得为了通过回归而降低并发约束或写入示例行情。
3. 全部标的成功时，`liveQuotes` 必须包含与请求集合一一对应的有效报价且错误态为空；部分失败时保留成功标的、明确提示稍后重试，并继续允许下一轮刷新，不得把部分成功误报为全量成功。
4. 重点池刷新仍只提交重点标的；该阶段不改变 15 秒/180 秒轮询、可见性暂停、手动刷新、数据渠道切换或用户状态 schema。

验收标准：Store 回归用 200 个自选验证请求集合无重复、全部完成和报价数量一致；并发上限、部分失败保留、重点池隔离和取消行为不回归；前端/Host 测试、架构审查、构建、安全审计和发布前 Web QA 通过。
