# 上市验收状态

更新时间：2026-09-05；本轮候选版本：0.1.220。

本文件记录验收证据与缺口，不以版本数量或静态架构检查代替实际验收。

## 当前版本

0.1.220 汇总相同前缀密钥替换、保存失败保留原数据，以及同源窗口凭据失效通知。成功保存/清除后通知其他窗口，接收窗口清理数据并重读 Host；旧请求不得覆盖新会话。消息不携带凭据或配置。不同端口、独立 Host/桌面进程不属于 BroadcastChannel 的覆盖范围。

## 必须继续验证的验收项

| 项目 | 当前证据 | 结论与下一步 |
| --- | --- | --- |
| 真实行情与对话 | 单元/Host 集成测试覆盖真实数据边界；固定 CAP 与模型探针已实现 | 自动化大多使用受控响应；需要用获授权的真实凭据，在安装后的 Windows/macOS 记录行情、详情、事件、对话的成功率和延迟，尚未证明上市可用性 |
| 凭据轮换 | 同前缀、失败保存、迟到响应和同源双标签页已验证 | 同源通知已覆盖；跨源、独立进程、外部凭据修改和进程休眠后的恢复尚未闭环 |
| 安装升级 | workflow 构建 DMG/EXE/MSI，配置包含稳定升级标识 | 构建通过不等于真实覆盖升级成功；需要干净系统上旧版安装→新版升级→配置/用户数据保留→卸载的验收记录 |
| 安装包信任 | 当前发布 workflow 未配置平台签名/公证步骤 | 签名身份和证书可用后接入，并在干净系统验证下载、启动提示与签名有效性 |
| 长期运行与费用 | 现有测试覆盖短缓存、并发、取消、费用提取、调度幂等 | 仍需跨交易时段的长期运行、断网恢复、休眠恢复测试，以及内存/请求次数/实际费用记录 |
| 发布交付 | 0.1.219 三类资产已下载校验；0.1.220 待流水线完成 | 每个版本必须核对正式 Release、三类安装包及校验和；未完成时明确标记待发布 |

## 后续实施顺序

1. Host 提供不含密钥的凭据版本标识，覆盖不同进程的读取、缓存隔离和写入竞争；窗口重新可见时从 Host 对账。
2. 建立真实数据跨端验收记录，分别记录冷/热缓存、部分失败、重试与费用；由实测确定性能目标。
3. 在 Windows/macOS 干净环境完成安装与升级测试，接入已有可用签名身份。
4. 做长期运行和休眠/断网恢复验收，再据证据判断是否满足上市要求。

这些缺口不应由无限增加局部 UI 功能来替代。当前仍属于验证中的迭代版本。
